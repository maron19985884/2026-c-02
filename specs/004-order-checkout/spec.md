# Feature Specification: 注文フォーム・注文完了画面

**Feature Branch**: `004-order-checkout`
**Created**: 2026-08-16
**Status**: Draft
**Input**: User description: "注文フォーム画面と注文完了画面を実装する。カート画面から「注文手続きへ」で遷移する注文フォームでは、氏名・住所・メールアドレス（3項目すべて必須）を入力でき、カート内の注文商品と合計金額を同一画面で確認できる。未入力や形式不正の場合はエラーメッセージを表示する。「注文する」ボタン1つで注文を確定すると、注文完了画面に遷移し、注文完了メッセージと注文番号を表示する。商品一覧へ戻るリンクも表示する。対応要件: requirements.md REQ-012〜REQ-018。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 注文内容を確認しながら顧客情報を入力する (Priority: P1)

カートから注文手続きへ進んだ利用者が、注文フォーム画面で氏名・住所・メールアドレスを入力する。その際、画面には自分が注文しようとしている書籍と合計金額が表示されており、入力しながら注文内容を確認できる。

**Why this priority**: 顧客情報の入力と注文内容の確認は、注文フォーム画面が存在する理由そのものであり、これがなければ注文確定(P2)に進めない。

**Independent Test**: カートに書籍が入っている状態で注文フォーム画面を開き、注文商品一覧・合計金額が表示され、氏名・住所・メールアドレスの入力欄が表示されることを確認すれば検証が完結する。

**Acceptance Scenarios**:

1. **Given** カートに1件以上の書籍が入っている、**When** 利用者がカート画面から「注文手続きへ」を選択する、**Then** 注文フォーム画面へ遷移し、カート内の注文商品と合計金額が表示される。
2. **Given** 注文フォーム画面が表示されている、**When** 利用者が画面を確認する、**Then** 氏名・住所・メールアドレスの入力欄が表示されている。

---

### User Story 2 - 入力ミスに気づき、注文を確定する (Priority: P2)

利用者が氏名・住所・メールアドレスを入力し、未入力や形式不正があればエラーメッセージで気づける。入力が揃った状態で「注文する」ボタンを押すと注文が確定し、注文完了画面に進む。

**Why this priority**: 顧客情報の確認(P1)を経て初めて意味を持つ操作であり、購買フロー全体を完了させる中心的な価値を持つため、確認の次に高い優先度とする。

**Independent Test**: 氏名・住所・メールアドレスのいずれかを未入力またはメールアドレスの形式を不正にした状態で「注文する」を押し、エラーメッセージが表示され画面に留まることを確認する。次に3項目すべて正しく入力して「注文する」を押し、注文完了画面へ遷移することを確認すれば検証が完結する。

**Acceptance Scenarios**:

1. **Given** 氏名・住所・メールアドレスのいずれかが未入力である、**When** 利用者が「注文する」ボタンを押す、**Then** 該当項目についてエラーメッセージが表示され、注文は確定しない。
2. **Given** メールアドレスの形式が不正である、**When** 利用者が「注文する」ボタンを押す、**Then** メールアドレスについてエラーメッセージが表示され、注文は確定しない。
3. **Given** 氏名・住所・メールアドレスがすべて有効な形式で入力されている、**When** 利用者が「注文する」ボタンを押す、**Then** 注文が確定し、注文完了画面へ遷移する。

---

### User Story 3 - 注文完了を確認し、一覧へ戻る (Priority: P3)

注文を確定した利用者が、注文完了画面で注文が受け付けられたことと注文番号を確認し、必要であれば商品一覧画面へ戻る。

**Why this priority**: 注文確定(P2)が成立して初めて到達する画面であり、確認と後片付けの位置づけのため、最も後の優先度とする。

**Independent Test**: 注文確定操作の後、注文完了メッセージと注文番号が表示され、商品一覧へ戻るリンクを選択すると商品一覧画面へ遷移することを確認すれば検証が完結する。

**Acceptance Scenarios**:

1. **Given** 利用者が注文を確定した、**When** 注文完了画面が表示される、**Then** 注文完了メッセージと注文番号が表示される。
2. **Given** 注文完了画面が表示されている、**When** 利用者が「商品一覧へ戻る」リンクを選択する、**Then** 商品一覧画面へ遷移する。

### Edge Cases

- カートが空の状態で注文フォーム画面に直接アクセスした場合、入力・注文確定はできない（`003-cart-management`の「カートが空の場合、注文手続きへ進めない」を前提とする。003 spec.md FR-011参照）。
- 氏名・住所は自由記述とし、形式チェックは行わない。未入力のみをエラーとする（`requirements.md`に文字数・文字種の制約が明記されていないため）。
- メールアドレスは形式（`local@domain`の基本構造）が不正な場合のみエラーとし、実在確認は行わない。
- 入力途中でカートの内容（合計金額等）を変更する手段は注文フォーム画面に設けない（カートへ戻って変更する）。
- 注文確定後、ブラウザの「戻る」で注文フォーム画面に戻っても、再度「注文する」を押せてしまうかどうかは本featureのスコープ外とし、実装時の挙動をそのまま許容する（決済処理を伴わない学習用途のため）。
- 注文番号は、注文確定時にバックエンドが新規APIを通じてデータベースに注文情報（顧客情報・注文商品・合計金額・注文番号）を永続化した上で発行する（ユーザー確認済み。「用語定義: システムが発行する一意の識別子」に忠実な方式）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、注文フォーム画面に、カート内の注文商品（書名・単価・数量・小計）と合計金額を表示しなければならない。
- **FR-002**: 利用者は、注文フォーム画面で氏名・住所・メールアドレスを入力できなければならない。
- **FR-003**: システムは、氏名・住所・メールアドレスのいずれかが未入力の状態で注文が確定されようとした場合、エラーメッセージを表示し、注文を確定してはならない。
- **FR-004**: システムは、メールアドレスの形式が不正な状態で注文が確定されようとした場合、エラーメッセージを表示し、注文を確定してはならない。
- **FR-005**: 利用者は、「注文する」ボタン1つの操作で注文を確定できなければならない。
- **FR-006**: システムは、注文確定後、注文完了画面へ遷移しなければならない。
- **FR-007**: システムは、注文完了画面に注文完了メッセージを表示しなければならない。
- **FR-008**: システムは、注文確定時にバックエンドで注文情報（顧客情報・注文商品・合計金額）を永続化し、一意の注文番号を発行して注文完了画面に表示しなければならない。
- **FR-009**: システムは、注文完了画面に商品一覧画面へ戻るリンクを表示しなければならない。
- **FR-010**: システムは、カートが空の状態では注文を確定できないようにしなければならない。

### Key Entities *(include if feature involves data)*

- **注文（Order）**: 1回の注文確定操作を表す。氏名・住所・メールアドレス（顧客情報）、注文商品（カート内容のスナップショット：書名・単価・数量・小計）、合計金額、注文番号を持つ。バックエンドで永続化される。
- **注文商品（Order Item）**: 注文に含まれる書籍1件分。注文確定時点の書名・単価・数量を保持する（後で書籍が販売対象外になっても注文内容自体は変わらない）。
- **注文番号（Order Number）**: 注文確定時にシステム（バックエンド）が発行する一意の識別子（`requirements.md`用語定義）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は、注文フォーム画面を離れることなく、注文内容（商品・合計金額）を確認しながら顧客情報を入力できる。
- **SC-002**: 氏名・住所・メールアドレスのいずれかが未入力またはメールアドレスの形式が不正な状態で「注文する」を押した利用者は、何が問題かをエラーメッセージから理解できる。
- **SC-003**: 3項目を正しく入力した利用者は、「注文する」ボタン1回の操作で注文完了画面まで到達できる。
- **SC-004**: 注文を確定した利用者は、注文完了画面で自分の注文を特定できる注文番号を確認できる。

## Assumptions

- 氏名・住所は自由記述の文字列とし、文字数・文字種の制約は設けない（要件定義書に明記がないための合理的デフォルト）。
- メールアドレスの形式チェックは、一般的な`local@domain`構造の妥当性検証とする（要件定義書に明記がないための合理的デフォルト）。
- 決済処理は本プロジェクト全体のスコープ外（`user_requirements.md`）であり、注文確定操作に決済は伴わない。
- 注文フォームへの直接アクセス時にカートが空である場合の具体的な画面挙動（リダイレクト等）は、003-cart-management spec.mdの「カートが空の場合はリンク切れで良い」という決定を踏襲し、注文フォームへの導線自体が存在しない状態を前提とする。
- 注文の永続化にあたり、在庫管理・注文ステータス管理（発送・キャンセル等）は本プロジェクト全体のスコープ外（`user_requirements.md`）であるため、`orders`テーブルは注文の記録のみを目的とし、状態遷移は持たない。
