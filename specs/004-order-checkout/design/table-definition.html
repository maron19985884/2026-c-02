3. order_items テーブル

3.1 カラム定義

物理名論理名型NULLデフォルトPK/FK説明
id注文商品IDINTNOT NULLAUTO_INCREMENTPK 注文商品明細を一意に識別するID
order_id注文IDINTNOT NULL-FK orders.idを参照。どの注文に属するか

quantity数量INTNOT NULL- 1以上の整数

3.2 インデックス定義

インデックス名種別対象カラム目的
PRIMARYPRIMARY KEYid一意識別
idx_order_items_order INDEX order_id 注文完了画面・将来の注文照会で「ある注文の明細一覧」を取得するクエリを効率化する

3.3 制約

制約内容
FOREIGN KEYorder_id → orders.id。ON DELETE CASCADE（注文自体を削除する操作は本機能にないが、将来の整合性のため設定）
FOREIGN KEYbook_id → books.id。ON DELETEは設定しない（書籍が削除されても注文明細のスナップショットは残す想定。ただし現状booksの削除操作自体が存在しないためスコープ外）
CHECK（アプリケーション側）quantity は1以上の整数（003 spec.md FR-009のカート側制約を踏襲）
整合性（アプリケーション側）1件の注文に紐づくorder_itemsは1件以上（空の注文は作成できない、spec.md FR-010）

4. 初期データ（シード）方針

mysql/init/02_orders_seed.sqlにて、orders・order_itemsテーブルをCREATE TABLE IF NOT EXISTSで作成する。初期データ（サンプル注文）は投入しない（注文はAPI経由でのみ作成されるべきデータであり、シードで作成した注文は実際の操作履歴と混同を招くため）。DROP・TRUNCATE・DELETEは含めない（CLAUDE.md「破壊的DDLの直接生成禁止」に対応）。
