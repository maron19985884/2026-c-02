# Feature Specification: カート画面

**Feature Branch**: `003-cart-management`
**Created**: 2026-08-16
**Status**: Draft
**Input**: User description: "個人運営オンライン書店のカート画面。カートに追加した書籍の書名・単価・数量・小計を一覧表示する。各書籍の数量を増減でき、変更すると小計と合計金額がリアルタイムに更新される。書籍をカートから削除でき、削除すると合計金額が即時更新される。カート内全書籍の合計金額（送料は対象外）を表示する。「注文手続きへ」ボタンで注文フォーム画面へ遷移する。ログイン・会員管理、決済処理、注文フォーム・注文完了自体、送料計算は本機能の対象外（別機能として扱う）。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - カートに入れた書籍を一覧で確認する (Priority: P1)

商品詳細画面等でカートに追加した書籍について、書名・単価・数量・小計と、カート全体の合計金額をカート画面で確認できる。

**Why this priority**: カートの中身が見えなければ、数量変更・削除・注文手続きのいずれの操作もできない。カート機能全体の前提となるため最優先とする。

**Independent Test**: カートに複数件の書籍が入っている状態でカート画面を開き、各行に書名・単価・数量・小計が表示され、画面全体に合計金額が表示されることを確認すれば検証が完結する。

**Acceptance Scenarios**:

1. **Given** カートに1件以上の書籍が入っている、**When** 利用者がカート画面を開く、**Then** カート内の各書籍について書名・単価・数量・小計が一覧表示される。
2. **Given** カート画面が表示されている、**When** 利用者が画面全体を確認する、**Then** カート内全書籍の小計を合計した金額が表示される。
3. **Given** カートに1件も書籍が入っていない、**When** 利用者がカート画面を開く、**Then** カートが空である旨のメッセージが表示される。
4. **Given** 商品一覧画面または商品詳細画面が表示されている、**When** 利用者がカートへの導線（リンク）を選択する、**Then** 書籍をカートに追加する操作を経由せずにカート画面へ遷移する。

---

### User Story 2 - 数量を変更する (Priority: P2)

カート画面で書籍の数量を増減し、変更結果が小計・合計に反映される。

**Why this priority**: カートの中身を確認できること(P1)が前提の操作。購入前に数量を調整するという、購買フローを前に進める上で価値のある操作だが、一覧確認より後の優先度とする。

**Independent Test**: カート画面で任意の書籍の数量を増減させ、その行の小計と画面全体の合計が、画面を再読み込みすることなく更新されることを確認すれば検証が完結する。

**Acceptance Scenarios**:

1. **Given** カート画面に書籍が表示されている、**When** 利用者がある書籍の数量を増やす、**Then** その書籍の小計と、カート全体の合計が増加した数量に応じて更新される。
2. **Given** ある書籍の数量が2以上である、**When** 利用者が数量を減らす、**Then** その書籍の小計と合計が減少した数量に応じて更新される。
3. **Given** ある書籍の数量が1である、**When** 利用者が数量をこれ以上減らそうとする、**Then** 数量は1未満にならない。

---

### User Story 3 - 不要な書籍をカートから削除する (Priority: P2)

カート画面で書籍を削除し、削除結果が合計に反映される。

**Why this priority**: 数量変更(US2)と同様、一覧確認(P1)が前提の操作。数量調整とは独立した操作のため同列の優先度とする。

**Independent Test**: カート画面である書籍を削除し、その行がカートから消え、画面全体の合計が削除後の内容に応じて更新されることを確認すれば検証が完結する。

**Acceptance Scenarios**:

1. **Given** カート画面に複数の書籍が表示されている、**When** 利用者がある書籍を削除する、**Then** その書籍がカートから消え、合計金額が削除後の内容に即時更新される。
2. **Given** カートに1件だけ書籍が入っている、**When** 利用者がその書籍を削除する、**Then** カートが空になり、カートが空である旨のメッセージが表示される。

---

### User Story 4 - 注文手続きに進む (Priority: P3)

カートの中身を確認・調整し終えた利用者が、注文フォーム画面へ進む。

**Why this priority**: カートの内容確認・調整(P1・P2)が完了して初めて意味を持つ導線であり、カート機能自体の主目的（内容の確認・編集）よりも後の優先度とする。

**Independent Test**: カート画面で「注文手続きへ」ボタンを押し、注文フォーム画面へ遷移することを確認すれば検証が完結する（遷移先の画面自体の内容は別機能の範囲）。

**Acceptance Scenarios**:

1. **Given** カートに1件以上の書籍が入っている、**When** 利用者が「注文手続きへ」ボタンを押す、**Then** 注文フォーム画面へ遷移する。

### Edge Cases

- カートに1件も書籍が入っていない場合、一覧はエラー表示ではなく「カートに書籍がありません」といった空状態を示す。
- 数量を1未満に減らす操作はできない（0にしたい場合は削除操作を用いる）。
- カートに入っている書籍が、その後販売対象外になっていた場合、該当行は購入対象外である旨を示すか一覧から除外する。
- カートが空の状態では「注文手続きへ」ボタンは意味を持たないため、押せない、または押しても注文フォームへは進めない。
- 数量・削除の操作結果は、ページを再読み込みしても保持されている。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、カートに追加された書籍について、書名・単価・数量・小計をカート画面に一覧表示しなければならない。
- **FR-002**: システムは、カート内全書籍の小計を合計した金額をカート画面に表示しなければならない。
- **FR-003**: 利用者は、カート内の各書籍の数量を増減できなければならない。
- **FR-004**: システムは、数量の変更に応じて、該当書籍の小計とカート全体の合計を、画面を再読み込みすることなく更新しなければならない。
- **FR-005**: 利用者は、カートから書籍を削除できなければならない。
- **FR-006**: システムは、削除操作に応じて合計金額を、画面を再読み込みすることなく更新しなければならない。
- **FR-007**: 利用者は、「注文手続きへ」ボタンを押すことで注文フォーム画面へ遷移できなければならない。
- **FR-008**: システムは、カートに書籍が1件も入っていない場合、その旨を示す空状態を表示しなければならない。
- **FR-009**: システムは、書籍の数量を1未満に減らせないようにしなければならない。
- **FR-010**: システムは、カートに入っている書籍が販売対象外になっている場合、その旨を利用者に示すか、当該書籍をカートの表示・合計計算から除外しなければならない。
- **FR-011**: システムは、カートが空の場合、注文手続きへ進めないようにしなければならない。
- **FR-012**: 利用者は、商品一覧画面・商品詳細画面から、書籍をカートに追加する操作を経由せずにカート画面へ遷移できなければならない（`requirements.md`画面遷移図の「一覧から直接も可」に対応）。

### Key Entities *(include if feature involves data)*

- **カート項目（Cart Item）**: カートに追加された書籍1件を表す。書籍ID・数量に加え、表示のために書籍の書名・単価・現在の販売可否を必要とする。小計は「単価×数量」で算出する。
- **カート合計（Cart Total）**: カート内全カート項目の小計を合計した金額。カート項目の変更（数量変更・削除）のたびに再計算される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: カート画面を開いた利用者は、追加の操作なしにカート内の書名・単価・数量・小計・合計を確認できる。
- **SC-002**: 数量変更操作を行った利用者は、画面を再読み込みすることなく更新後の小計・合計を確認できる。
- **SC-003**: 削除操作を行った利用者は、画面を再読み込みすることなく更新後の合計を確認できる。
- **SC-004**: カートが空の状態でアクセスした利用者は、エラーと誤解せず「カートに何も入っていない」と理解できる。

## Assumptions

- カートの永続化は、002-book-catalog-detail feature で実装済みのブラウザ`localStorage`を継続利用し、ページを再読み込みしても内容が保持される。
- 数量の下限は1とし、0にする操作は「削除」として扱う（要件定義書に明記がないための合理的デフォルト）。
- 数量の上限は設けない（要件定義書に明記がないための合理的デフォルト）。
- カートに登録済みの書籍がその後販売対象外になっていた場合の具体的な表示方法（除外か注記か）は実装時に決定する。在庫管理・販売終了管理自体は本プロジェクト全体のスコープ外（`user_requirements.md`）。
- 送料は要件定義書により対象外（`requirements.md` REQ-010）。
- 注文フォーム画面自体（入力項目・バリデーション・注文確定処理）は別機能（次feature）の責務であり、本機能では「注文手続きへ」ボタンによる画面遷移のみを扱う。
- ログイン・会員管理は本プロジェクト全体のスコープ外であるため、カートの閲覧・編集は匿名の利用者として行える。
