# Feature Specification: カート画面

**Feature Branch**: `006-cart-page`
**Created**: 2026-09-09
**Status**: Draft
**Input**: User description: "カート画面: カート内の各書籍の書名・単価・数量・小計を一覧表示する。数量を増減でき、小計と合計がリアルタイムに更新される。書籍をカートから削除でき、削除後に合計金額が即時更新される。カート内全商品の合計金額を表示する。「注文手続きへ」ボタンで注文フォーム画面へ遷移する。(REQ-007, REQ-008, REQ-009, REQ-010, REQ-011)"

## Clarifications

### Session 2026-09-09

- Q: カート内の書籍の数量が1件の状態でさらに「減らす」操作をした場合、どう振る舞いますか？ → A: 1未満にはできない（減少ボタンを無効化し、数量1が下限。カートから外すには別途「削除」操作を行う）
- Q: カートが空（0件）のとき、「注文手続きへ」ボタンはどう扱いますか？ → A: 非表示にする（空状態メッセージと一覧へ戻る導線のみを表示する）
- Q: カート内の数量変更は、どの操作方法を許可しますか？ → A: +/-ボタンのみ（数量欄への直接数値入力は行わない）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - カートの内容を確認する (Priority: P1)

購入希望者として、カート画面でカートに入れた各書籍の書名・単価・数量・小計を一覧で確認できるようにしたい。これにより、注文手続きに進む前に購入内容を正確に把握できる。

**Why this priority**: カート内容を確認できなければ、数量変更・削除・注文手続きへの遷移といった以降の操作が成立しない。要件定義書でも REQ-007 は優先度「高」。

**Independent Test**: 1件以上の書籍がカートに入っている状態でカート画面を開き、各行に書名・単価・数量・小計が表示されることを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** カートに書籍が2件入っている、**When** 購入希望者がカート画面を開く、**Then** 各書籍について書名・単価・数量・小計（単価×数量）が1行ずつ表示される。
2. **Given** カートに書籍が1件も入っていない、**When** 購入希望者がカート画面を開く、**Then** カートが空であることを示す空状態メッセージが表示され、エラーとは区別できる。

---

### User Story 2 - カート内の数量を変更する (Priority: P1)

購入希望者として、カート画面上で各書籍の数量を増減し、その場で小計・合計金額が更新されるのを確認できるようにしたい。これにより、購入冊数を画面遷移なく調整できる。

**Why this priority**: 数量調整はカート画面の中心機能であり、これがないと注文内容を確定させる前に冊数を見直す手段がない。要件定義書でも REQ-008 は優先度「高」。

**Independent Test**: カートに書籍が1件入っている状態で数量の増加・減少ボタンを操作し、当該行の小計とカート全体の合計が即座に再計算されることを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** カートにある書籍の数量が1件、**When** 購入希望者が数量の増加ボタンを押す、**Then** 数量が1増え、その行の小計とカート全体の合計が画面遷移なく即時に更新される。
2. **Given** カートにある書籍の数量が2件以上、**When** 購入希望者が数量の減少ボタンを押す、**Then** 数量が1減り、その行の小計とカート全体の合計が画面遷移なく即時に更新される。
3. **Given** カートにある書籍の数量が1件、**When** 購入希望者が数量の減少ボタンを押そうとする、**Then** 減少ボタンは無効化されており数量は1未満にならない（[Clarifications Session 2026-09-09](#clarifications) 参照）。
4. **Given** カート画面が表示されている、**When** 購入希望者が数量を増減する、**Then** 増減の操作手段は+/-ボタンのみであり、数量欄への直接入力はできない（[Clarifications Session 2026-09-09](#clarifications) 参照）。

---

### User Story 3 - カートから書籍を削除する (Priority: P1)

購入希望者として、不要になった書籍をカートから削除し、削除後にカート全体の合計金額が更新されるのを確認できるようにしたい。これにより、購入意思のない書籍を注文内容から確実に除外できる。

**Why this priority**: 削除手段がないと、誤って追加した書籍や購入をやめた書籍を注文内容から外せず、意図しない注文につながる。要件定義書でも REQ-009 は優先度「高」。

**Independent Test**: カートに書籍が2件入っている状態で1件を削除し、その行が一覧から消え、合計金額が削除前より減少することを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** カートに書籍が2件入っている、**When** 購入希望者がそのうち1件の削除操作を行う、**Then** 当該書籍の行がカート一覧から消え、カート全体の合計金額が削除した書籍の小計分だけ即時に減少する。
2. **Given** カートに書籍が1件だけ入っている、**When** 購入希望者がその書籍を削除する、**Then** カートは空になり、空状態メッセージが表示される。

---

### User Story 4 - カート全体の合計金額を確認する (Priority: P1)

購入希望者として、カート内全書籍の合計金額を常に画面上で確認できるようにしたい。これにより、注文手続きに進む前に支払う金額の見込みを把握できる。

**Why this priority**: 合計金額が分からないまま注文手続きへ進むと、購入の意思決定に必要な情報が欠けてしまう。要件定義書でも REQ-010 は優先度「高」。

**Independent Test**: カートに書籍が複数件入っている状態でカート画面を開き、表示される合計金額が各行の小計の総和と一致することを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** カートに単価の異なる書籍が複数件入っている、**When** 購入希望者がカート画面を開く、**Then** 各行の小計の総和と一致する合計金額が画面上に表示される。
2. **Given** カート画面が表示されている、**When** 数量変更または削除によりカート内容が変化する、**Then** 合計金額はその都度、画面遷移なく再計算され表示される（User Story 2, 3 参照）。

---

### User Story 5 - 注文手続きへ進む (Priority: P1)

購入希望者として、カート内容を確認したうえで「注文手続きへ」ボタンを押し、注文フォーム画面へ進めるようにしたい。これにより、購入フローを次のステップへ進められる。

**Why this priority**: この導線がないと、カートの内容を確認した後に注文を完了させる手段がなく、購買フロー全体が完結しない。要件定義書でも REQ-011 は優先度「高」。

**Independent Test**: カートに書籍が1件以上入っている状態で「注文手続きへ」ボタンを押し、注文フォーム画面へ遷移することを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** カートに書籍が1件以上入っている、**When** 購入希望者が「注文手続きへ」ボタンを押す、**Then** 注文フォーム画面へ遷移する。
2. **Given** カートが空（0件）の状態でカート画面が表示されている、**When** 購入希望者がカート画面を見る、**Then** 「注文手続きへ」ボタンは表示されない（[Clarifications Session 2026-09-09](#clarifications) 参照）。

---

### Edge Cases

- カートが空（0件）の場合、一覧のかわりに空状態メッセージを表示し、エラー表示とは区別する（商品一覧画面の空状態方針と同様の考え方を適用。User Story 1 参照）。
- カートが空（0件）の場合、「注文手続きへ」ボタンは表示せず、商品一覧へ戻る導線を提示する（[Clarifications Session 2026-09-09](#clarifications) 参照）。
- カート内の書籍の数量が1件のとき、減少ボタンは無効化され、数量は1未満にならない。カートから外すには「削除」操作を用いる（[Clarifications Session 2026-09-09](#clarifications) 参照）。
- 数量の増減に上限は設けない（在庫管理を行わないため。[spec 005](../005-book-detail-page/spec.md) の方針を踏襲）。
- カート内の商品情報（書名・単価等）は追加時点の内容を保持し、カート画面表示中に元の書籍情報が変わっても、カート画面自体の再読み込みなしに反映される必要はない（本画面の表示更新契機は数量変更・削除操作に限る）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、カート画面にカート内の各書籍について書名・単価・数量・小計（単価×数量）を1行ずつ一覧表示しなければならない（REQ-007）。
- **FR-002**: システムは、カートが空（0件）の場合、一覧の代わりに空状態メッセージを表示し、エラー表示とは異なる見た目・文言で区別しなければならない（Edge Cases 参照）。
- **FR-003**: システムは、カート内の各書籍について数量を増加・減少できる操作（+/-ボタン）を提供しなければならない（REQ-008）。数量欄への直接数値入力は提供しない（[Clarifications Session 2026-09-09](#clarifications) 参照）。
- **FR-004**: システムは、数量が変更された際、当該行の小計およびカート全体の合計金額を、画面遷移や再読み込みを伴わずに即時に再計算・表示しなければならない（REQ-008）。
- **FR-005**: システムは、書籍の数量が1件の状態で減少操作が行われても数量が1未満にならないようにし、減少ボタンを無効化しなければならない（[Clarifications Session 2026-09-09](#clarifications) 参照）。数量の増加に上限は設けない。
- **FR-006**: システムは、カート内の各書籍について、当該書籍をカートから削除する操作を提供しなければならない（REQ-009）。
- **FR-007**: システムは、書籍が削除された際、当該行を一覧から取り除き、カート全体の合計金額を画面遷移や再読み込みを伴わずに即時に更新しなければならない（REQ-009）。
- **FR-008**: システムは、カート内全書籍の小計の総和を合計金額としてカート画面上に常時表示しなければならない（REQ-010）。送料等は合計に含めない（要件定義書§2 対象外）。
- **FR-009**: システムは、カートに1件以上の書籍が入っている場合、「注文手続きへ」ボタンを表示し、押下時に注文フォーム画面へ遷移させなければならない（REQ-011）。
- **FR-010**: システムは、カートが空（0件）の場合、「注文手続きへ」ボタンを表示してはならない（[Clarifications Session 2026-09-09](#clarifications) 参照）。この場合、商品一覧画面へ戻る導線を提示しなければならない。
- **FR-011**: カート画面は未ログインの一般利用者が会員登録なしで閲覧・操作できなければならない（要件定義書§2 対象範囲、ログイン・会員管理は対象外）。

### Key Entities

- **カート項目（CartItem）**: 購入希望者が購入予定の書籍を一時的に保持する単位。対象書籍への参照（書名・単価を含む）と数量（1以上の整数、上限なし）を持つ。数量変更・削除の対象となる。
- **カート（Cart）**: カート項目の集合。0件（空）から複数件を保持でき、全カート項目の小計の総和として合計金額を導出する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 購入希望者は、カートに書籍が入っている状態でカート画面を開いた直後に、追加の操作なしで各書籍の書名・単価・数量・小計を視認できる。
- **SC-002**: 購入希望者が数量の増加・減少ボタンを押してから、その行の小計とカート全体の合計金額が更新されるまでに、画面遷移や再読み込みは一切発生しない。
- **SC-003**: 購入希望者が書籍を削除してから、当該行が一覧から消え、合計金額が更新されるまでに、画面遷移や再読み込みは一切発生しない。
- **SC-004**: カート内の数量がいずれの値であっても、表示される合計金額は常に「各行の小計の総和」と一致する（金額の不整合が発生しない）。
- **SC-005**: 数量が1件の書籍について、減少操作をどれだけ試みても数量が0や負の値にならない。
- **SC-006**: カートが空（0件）のとき、購入希望者は「注文手続きへ」ボタンが存在しないことと空状態メッセージから、カートに何も入っていないことを一目で判別できる。
- **SC-007**: カートに1件以上の書籍が入っている状態で「注文手続きへ」ボタンを押してから、注文フォーム画面が表示されるまでの遷移は1回の操作で完了する。

## Assumptions

- カートの状態（商品詳細画面からの追加内容）は、本画面を開いた時点で既に保持されていることを前提とし、カート状態の永続化方式（ブラウザ内保持か否か等）は技術選定書の実装方針に従う。本仕様ではカートの表示・操作のみを規定する。
- 数量の増減操作は+/-ボタンのみとし、数量欄への直接数値入力は提供しない（[Clarifications Session 2026-09-09](#clarifications) 参照）。
- 数量の下限は1、上限は設けない（在庫管理を行わないため。[spec 005](../005-book-detail-page/spec.md) の方針を踏襲）。
- カートを空にする一括操作（全削除ボタン等）は要件定義書に明記がないため本画面では提供しない。書籍ごとの削除操作の繰り返しで対応する。
- カート画面のレイアウト・デザインの詳細（列構成、レスポンシブ対応の具体仕様等）は技術選定書に定めるCSS方針（CSS Modules）に従い、設計フェーズ（`/speckit.plan`）で具体化する。
- 読み込み中（ローディング）状態の表示有無・具体的な見た目は本仕様では規定せず、設計フェーズで憲法§3のUX一貫性方針に沿って具体化する。
- 検索・フィルター・レビュー・評価などは要件定義書§2で対象外と明記されている（本画面にも適用）。
