# Feature Specification: 個人運営オンライン書店 購買フロー

**Feature Branch**: `003-bookstore-purchase-flow`
**Created**: 2026-09-02
**Status**: Draft
**Input**: User description: "個人運営オンライン書店の購買フロー特化アプリ。未ログインの購入希望者が『商品一覧→商品詳細→カート→注文フォーム→注文完了』の5画面を通して、欲しい本を見つけ、氏名・住所・メールアドレスを入力して注文を完了できる。会員管理・決済・在庫管理・管理画面・レビュー・検索/フィルターはスコープ外。詳細は requirements.md（および入力元の user_requirements.md）を参照。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 書籍を選んで注文を完了する (Priority: P1)

書店サイトを訪れた購入希望者が、販売中の書籍の一覧を眺め、気になった本の詳細を確認し、カートに入れて注文フォームで氏名・住所・メールアドレスを入力し、注文を確定して完了画面に到達する。ログインや支払い手続きは発生しない。

**Why this priority**: これがアプリの存在価値そのもの。この一気通貫の導線が成立しなければ「書店」として機能しない。ほかの機能はすべてこの導線の品質を高める補助である。

**Independent Test**: 何も設定していない初回訪問状態から、書籍1冊を選び、注文フォームに有効な3項目を入力し、注文完了画面に注文番号が表示されるところまでを単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 販売中の書籍が複数登録されている, **When** 利用者が商品一覧を開く, **Then** 書影・タイトル・著者・価格を伴った書籍カードがグリッド形式で一覧表示される
2. **Given** 商品一覧が表示されている, **When** 利用者が任意の書籍カードを選択する, **Then** その書籍の商品詳細画面へ遷移し、書影・タイトル・著者・価格・説明文が表示される
3. **Given** 商品詳細画面を見ている, **When** 利用者が「カートに追加」を押す, **Then** 当該書籍がカートに入り、利用者は商品一覧へ戻って閲覧を続けられる
4. **Given** カートに1冊以上入っている, **When** 利用者がカート画面を開く, **Then** 各書籍の書名・単価・数量・小計と、全体の合計金額が表示される
5. **Given** カート画面を見ている, **When** 利用者が「注文手続きへ」を押す, **Then** 注文フォーム画面へ遷移し、同一画面に注文商品と合計金額が表示される
6. **Given** 注文フォームに氏名・住所・メールアドレスを正しく入力した, **When** 利用者が「注文する」を押す, **Then** 注文が確定し、注文完了画面へ遷移する
7. **Given** 注文が確定した, **When** 注文完了画面が表示される, **Then** 注文完了メッセージ・注文を特定できる注文番号・商品一覧へ戻るリンクが表示される

---

### User Story 2 - カートの中身を調整する (Priority: P2)

利用者が注文前に、カートに入れた書籍の数量を増減したり、不要になった書籍を削除したりして、購入内容を思いどおりに組み立てる。変更のたびに小計と合計がその場で更新され、支払う金額を常に把握できる。

**Why this priority**: 注文フロー自体（US1）が動けば最小限の買い物は成立するが、数量調整・削除ができないと「まとめ買い」や「入れ間違いの訂正」ができず実用に耐えない。US1 の次に重要。

**Independent Test**: カートに複数書籍を入れた状態から、数量変更・削除を行い、そのたびに小計・合計が正しい金額へ即座に更新されることを、注文確定まで進めずに単独で検証できる。

**Acceptance Scenarios**:

1. **Given** カートに書籍Aが数量1で入っている, **When** 利用者が数量を2に増やす, **Then** 書籍Aの小計が単価×2に変わり、合計金額も即座に更新される
2. **Given** カートに書籍Aが数量2で入っている, **When** 利用者が数量を1に減らす, **Then** 小計と合計が即座に再計算されて表示される
3. **Given** カートに書籍A・書籍Bが入っている, **When** 利用者が書籍Aを削除する, **Then** 一覧から書籍Aの行が消え、合計金額が書籍Bのみの金額へ即座に更新される
4. **Given** カートに書籍が1冊だけ入っている, **When** 利用者がその書籍を削除する, **Then** カートが空であることが利用者に分かる形で表示される

---

### User Story 3 - 入力ミスに気づいて修正する (Priority: P2)

利用者が注文フォームで氏名・住所・メールアドレスを入力する際、未入力のまま、あるいは形式が不正なまま注文を確定しようとすると、どこに問題があるかがエラーメッセージで示され、修正してから注文を完了できる。

**Why this priority**: 3項目すべて必須であり、誤った連絡先で注文が確定すると個人運営者が注文者に到達できなくなる。US1 の happy path を守るためのガードとして P2。

**Independent Test**: 注文フォーム画面だけを対象に、各項目を空にする／メールアドレスを不正な形式にするパターンで「注文する」を押し、対応するエラー表示が出て注文が確定しないことを単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 注文フォームで氏名が未入力, **When** 利用者が「注文する」を押す, **Then** 氏名が必須である旨のエラーメッセージが表示され、注文完了画面へ遷移しない
2. **Given** 注文フォームで住所が未入力, **When** 利用者が「注文する」を押す, **Then** 住所が必須である旨のエラーメッセージが表示され、注文は確定しない
3. **Given** 注文フォームでメールアドレスが形式不正（例: `@` を含まない）, **When** 利用者が「注文する」を押す, **Then** メールアドレスの形式が不正である旨のエラーメッセージが表示され、注文は確定しない
4. **Given** すべての必須項目が正しく入力されている, **When** 利用者が「注文する」を押す, **Then** エラーは表示されず、注文が確定して注文完了画面へ遷移する

---

### Edge Cases

- **カートが空の状態でカート画面／注文フォーム画面を開いた**とき: 空である旨を表示し、注文手続きへ進めない（または注文を確定できない）こと
- **数量を1未満（0・マイナス）に変更しようとした**とき: 数量は最小1として扱う（それ以下にしたい場合は削除操作を使う）
- **同一書籍を複数回カートに追加した**とき: 別明細を増やさず、その書籍の数量を加算する（CL-002）
- **存在しない書籍の詳細画面を直接開いた**とき: 該当書籍が見つからない旨を表示し、商品一覧へ戻れること
- **販売中の書籍が0件**のとき: 商品一覧に「販売中の書籍がありません」等の空状態を表示すること
- **注文確定後にブラウザの戻る操作で注文フォームに戻り、再度「注文する」を押した**とき: 注文確定時にカートは空になる（FR-020a）ため、カートが空である旨が表示され注文は確定しない。意図せぬ重複注文を防ぐ
- **書名・著者名が非常に長い**場合でも一覧・カートのレイアウトが崩れないこと
- **商品一覧で範囲外のページを要求した**とき（存在しないページ番号など）: 先頭ページまたは空でないページへ丸める、もしくは空状態として扱い、利用者が有効なページへ戻れること
- **API通信が失敗した**とき（一覧取得・詳細取得・注文送信）: 汎用エラーメッセージを表示する。自動リトライ・再試行ボタンは設けない（FR-032）
- **ページのリロード／再訪**時: 同一ブラウザなら直近のカートを復元する。別ブラウザ・別デバイスとは同期しない（CL-001）

## Requirements *(mandatory)*

### Functional Requirements

#### 商品一覧（画面1）

- **FR-001**: システムは販売中の書籍をグリッド形式で一覧表示できること（対応: REQ-001 / U-01）
- **FR-002**: システムは一覧上の各書籍について書影・タイトル・著者・価格を表示すること（対応: REQ-002 / U-02）
- **FR-003**: 利用者は一覧上の書籍を選択して、その書籍の商品詳細画面へ遷移できること（対応: REQ-003 / U-03）
- **FR-004**: 販売中の書籍が0件の場合、システムは空状態であることを利用者に伝える表示を行うこと

#### 商品詳細（画面2）

- **FR-005**: システムは選択された書籍の書影・タイトル・著者・価格・説明文を表示すること（対応: REQ-004 / U-04）
- **FR-006**: 利用者は「カートに追加」操作1つで当該書籍をカートに追加できること（対応: REQ-005 / U-05）
- **FR-007**: 利用者はカートに追加した後も商品一覧へ戻って閲覧を続けられること（対応: REQ-006 / U-06）
- **FR-008**: 指定された書籍が存在しない場合、システムは見つからない旨を表示し商品一覧へ戻る導線を提供すること

#### カート（画面3）

- **FR-009**: システムはカート内の各書籍について書名・単価・数量・小計を一覧表示すること（対応: REQ-007 / U-07）
- **FR-010**: 利用者はカート内の各書籍の数量を増減でき、変更に応じて小計と合計が即座に更新されること（対応: REQ-008 / U-08）
- **FR-011**: 利用者はカート内の書籍を削除でき、削除に応じて合計金額が即座に更新されること（対応: REQ-009 / U-09）
- **FR-012**: システムはカート内全書籍の合計金額を表示すること。送料等の加算・表示は行わないこと（対応: REQ-010 / U-10）
- **FR-013**: 利用者は「注文手続きへ」操作で注文フォーム画面へ遷移できること（対応: REQ-011 / U-11）
- **FR-014**: 小計は「単価 × 数量」、合計は「カート内全書籍の小計の総和」として算出すること
- **FR-015**: 数量の下限は1とし、それ未満にする操作は数量1に留めること（削除は FR-011 で行う）
- **FR-016**: カートが空の場合、システムは空である旨を表示し、注文手続きへ進めないこと

#### 注文フォーム（画面4）

- **FR-017**: 利用者は氏名・住所・メールアドレスを入力でき、3項目すべてを必須とすること（対応: REQ-012 / U-12）
- **FR-018**: いずれかの必須項目が未入力、またはメールアドレスの形式が不正な場合、システムは該当項目のエラーメッセージを表示し、注文を確定しないこと（対応: REQ-013 / U-13）
- **FR-019**: システムは注文フォームと同一画面に注文商品と合計金額を表示すること（対応: REQ-014 / U-14）
- **FR-020**: すべての必須項目が妥当な場合、利用者は「注文する」操作1つで注文を確定し、注文完了画面へ遷移できること（対応: REQ-015 / U-15）
- **FR-020a**: 注文が確定したら、システムはカートの中身を空にすること（CL-004）

#### 注文完了（画面5）

- **FR-021**: システムは注文確定時に注文完了メッセージを表示すること（対応: REQ-016 / U-16）
- **FR-022**: システムは注文を一意に特定できる注文番号を発行し、注文完了画面に表示すること（対応: REQ-017 / U-17）
- **FR-023**: システムは注文完了画面に商品一覧へ戻るリンクを表示すること（対応: REQ-018 / U-18）
- **FR-024**: システムは確定した注文（注文番号・注文者情報・注文明細・合計金額・注文日時）を永続化すること
- **FR-024a**: 注文明細には注文時点の書名・単価をスナップショットとして保存し、以後に書籍の価格や書名が変更されても確定済み注文の内容は変わらないこと（CL-005）

#### 横断・非機能

- **FR-025**: システムはログイン・会員登録を要求せず、未認証の利用者が全画面を利用できること
- **FR-026**: システムは決済処理・在庫管理・管理画面・レビュー・検索/フィルターを提供しないこと（スコープ外）
- **FR-027**: 画面遷移・エラー表示・空状態（データ0件時）の扱いを全画面で統一すること
- **FR-028**: 注文者が入力する個人情報は氏名・住所・メールアドレスの3項目に限定すること
- **FR-029**: システムはカートをサーバに保持せず、利用者のブラウザ内に保存すること。同一ブラウザではリロード後も直近のカート内容を復元し、別ブラウザ・別デバイスとは同期しないこと（CL-001）
- **FR-030**: 既にカートに存在する書籍を「カートに追加」した場合、システムは新たな明細を作らず当該明細の数量を1加算すること（CL-002）
- **FR-031**: 商品一覧はページング形式で表示すること。1ページあたりの表示件数と前後ページへの移動手段を備え、利用者は全ページの書籍を辿れること（CL-006、1ページの件数は設計フェーズで確定）
- **FR-032**: API通信（書籍一覧取得・書籍詳細取得・注文送信など）が失敗した場合、システムは汎用的なエラーメッセージを表示すること。自動リトライや再試行ボタンは提供しない（CL-007）

### Key Entities *(include if feature involves data)*

- **書籍 (Book)**: 販売対象の商品。属性: 識別子、タイトル、著者、価格、書影（画像参照）、説明文。商品一覧・商品詳細で参照される
- **カート (Cart)**: 一人の利用者が購入予定の書籍を一時的に保持する入れ物。0個以上のカート明細を持つ
- **カート明細 (CartItem)**: カート内の1書籍分のエントリ。属性: 対象書籍、数量（1以上）。小計は「書籍の価格 × 数量」で導出
- **注文 (Order)**: 確定した1回の注文。属性: 注文番号（一意）、注文者氏名、注文者住所、注文者メールアドレス、合計金額、注文日時。1個以上の注文明細を持つ
- **注文明細 (OrderLineItem)**: 注文に含まれる1書籍分の記録。属性: 書籍への参照、注文時点のスナップショット（書名・単価）、数量、小計（スナップショット単価 × 数量）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初回訪問の利用者が、事前説明なしで商品一覧から注文完了画面（注文番号表示）まで到達できる。所要操作は5画面の遷移のみで、外部ヘルプを要しない
- **SC-002**: カートでの数量変更・書籍削除の結果が、合計金額へ体感的に即時（1秒以内）反映される
- **SC-003**: 必須3項目のいずれかが未入力、またはメールアドレス形式不正の状態からの注文確定は100%阻止され、どの項目が問題かが利用者に示される
- **SC-004**: 注文確定のたびに一意な注文番号が発行され、異なる注文間で注文番号が重複しない
- **SC-005**: 注文完了画面から1操作で商品一覧へ戻れる
- **SC-006**: カートの合計金額が、常に「各明細の（単価×数量）の総和」と一致する（送料等の付加なし）
- **SC-007**: 確定した注文の内容（注文者情報・明細・合計・注文日時）が永続化され、後から注文番号で特定できる

## Assumptions

- 対象利用者は未ログインの一般購入希望者であり、1人が1つのカートを操作する前提とする。複数利用者間のカート共有・同期は考慮しない
- 書籍データ（在庫数を含まない販売中の書籍カタログ）は事前に登録済みであることを前提とする。書籍の登録・編集手段はスコープ外
- 「販売中」であれば数量制限なく注文できる。在庫切れ・購入上限の概念は持たない（在庫管理がスコープ外のため）
- 決済は行わないため、注文確定＝「注文の受付」であり、入金確認・発送は本アプリの対象外
- 送料・税・割引の計算は行わず、合計金額は書籍価格の単純合算とする
- 注文確定後の注文内容の変更・キャンセルはスコープ外
- 動作環境はローカル環境での単一利用者を前提とし、同時実行・高負荷は考慮しない

## Clarifications

### Session 2026-09-02

- Q: ページのリロードや再訪問時にカートの中身を保持するか → A: ブラウザ側に保持する（サーバにカートを持たず、クライアント保存（localStorage 等）で同一ブラウザならリロード後も直近のカートを復元。別デバイス・別ブラウザ間の同期は行わない）
- Q: カートに入っている書籍を再度「カートに追加」したときの挙動 → A: 既存明細の数量を +1 する（明細行は増やさない）
- Q: 注文番号の形式 → A: 一意な英数字の識別子とし、具体的な形式は設計フェーズで確定する（利用者が読み上げ・書き写ししやすいこと）

### Session 2026-09-03

- Q: 注文確定（「注文する」成功）の後、カートの中身はどうなるか → A: 空にする
- Q: 注文明細に保存する「書名・単価」は → A: 注文時点のスナップショットを保存する
- Q: 商品一覧の表示範囲 → A: ページングあり（1ページの件数は設計で確定）
- Q: API通信エラー（一覧取得失敗・注文送信失敗など）時の振る舞い → A: 汎用エラー表示のみ（自動リトライ・再試行ボタンなし）

### 上記を反映した確定事項

- **CL-001**: カートはサーバに永続化せず、クライアント（ブラウザ）に保存する。同一ブラウザ内ではリロード後もカートを復元する。異なるブラウザ／デバイス間での共有・同期は行わない（→ FR-029）
- **CL-002**: 商品詳細で既にカート内にある書籍を「カートに追加」した場合、新たな明細を作らず当該明細の数量を +1 する（→ FR-030、Edge Cases「同一書籍を複数回カートに追加した」）
- **CL-003**: 注文番号は注文ごとに一意な英数字の識別子とする。桁数・プレフィックス等の具体形式は設計フェーズ（`/speckit.plan`）で決定する（→ FR-022）
- **CL-004**: 注文が確定したらカートを空にする（→ FR-020a、Edge Cases「注文確定後にブラウザの戻る操作で…」）
- **CL-005**: 注文明細には注文時点の書名・単価をスナップショット保存し、以後の書籍変更が確定済み注文に影響しないようにする（→ FR-024a、Key Entities「注文明細」）
- **CL-006**: 商品一覧はページング表示とする。1ページの表示件数と前後ページ移動手段を備える。件数の具体値は設計フェーズで決定する（→ FR-031、Edge Cases「範囲外のページ」）
- **CL-007**: API通信失敗時は汎用エラーメッセージのみを表示する。自動リトライ・再試行ボタンは設けない（→ FR-032、Edge Cases「API通信が失敗した」）
