# Feature Specification: 商品詳細画面

**Feature Branch**: `005-book-detail-page`
**Created**: 2026-09-09
**Status**: Draft
**Input**: User description: "商品詳細画面: 商品詳細画面で書影・タイトル・著者・価格・説明文を表示する。「カートに追加」ボタン押下のみで当該書籍をカートに追加できる。カートに追加した後もそのまま商品一覧へ戻って閲覧を続けられる。(REQ-004, REQ-005, REQ-006)"

## Clarifications

### Session 2026-09-09

- Q: 存在しない書籍ID（削除済み・不正URL）で商品詳細画面にアクセスした場合、どう表示しますか？ → A: 共通エラー表示を流用（商品一覧画面と同一の共通エラー表示パターンを用いる。専用の「見つかりません」画面は新設しない）
- Q: 既にカートにある書籍を再度「カートに追加」した場合、数量はどう扱いますか？ → A: 数量を+1で加算（既存のカート項目の数量に加算し、行は増やさない）
- Q: 「カートに追加」ボタン押下後、成功をどう利用者に伝えますか？ → A: ボタン表記を一時変化（例:「追加しました」のように短時間ボタンの表記を変える。専用の通知コンポーネントは新設しない）
- Q: 商品詳細画面（および今後のカート・注文画面）で扱う価格は、税込み・税抜きのどちらを前提としますか？ → A: 税込み価格のみを保持・表示する（税抜き価格の保持や税率計算ロジックは持たない）
- Q: 「カートに追加」を連打するなどして同一書籍の数量が増え続ける場合、上限を設けますか？ → A: 上限なし（在庫管理を行わないため、数量に上限を設けない）
- Q: 「カートに追加」ボタンを短時間に連続でクリック（連打・ダブルクリック）した場合、各クリックをそれぞれ+1として反映しますか？ → A: 常にクリックごとに+1（連打防止・デバウンスは行わない）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 書籍の詳しい情報を確認する (Priority: P1)

購入希望者として、商品一覧で気になった書籍の詳細画面を開き、書影・タイトル・著者・価格・説明文を確認できるようにしたい。これにより、一覧の情報だけでは分からない内容（説明文など）を踏まえて購入を判断できる。

**Why this priority**: 詳細情報の表示は本画面の存在意義そのものであり、これがなければ購入判断に必要な情報が得られない。要件定義書でも REQ-004 は優先度「高」。

**Independent Test**: 書籍が1件存在する状態でその書籍の商品詳細画面を開き、書影・タイトル・著者・価格・説明文の5項目が表示されることを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 販売中の書籍が1件登録されている、**When** 購入希望者がその書籍の商品詳細画面を開く、**Then** 当該書籍の書影・タイトル・著者・価格・説明文が表示される。
2. **Given** ある書籍に書影データが設定されていない、**When** その書籍の商品詳細画面を開く、**Then** 書影の代わりに全書籍共通のプレースホルダー画像が表示され、タイトル・著者・価格・説明文は通常どおり表示される（商品一覧画面と同様のプレースホルダー方針。[spec 004](../004-book-list-page/spec.md) 参照）。

---

### User Story 2 - 書籍をカートに追加する (Priority: P1)

購入希望者として、商品詳細画面で「カートに追加」ボタンを押すだけで、当該書籍をカートに追加できるようにしたい。これにより、購入したい書籍を数量入力などの手間なく素早くカートに入れられる。

**Why this priority**: カートへの追加は購買フローを先に進めるための唯一の導線であり、これがないと詳細画面から購入手続きへ進めない。要件定義書でも REQ-005 は優先度「高」。

**Independent Test**: 商品詳細画面で「カートに追加」ボタンを押し、その書籍がカートに追加されている（数量1件として計上される）ことを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 商品詳細画面が表示されている、**When** 購入希望者が「カートに追加」ボタンを押す、**Then** 当該書籍が数量1件としてカートに追加される。
2. **Given** カートに未登録の書籍の詳細画面が表示されている、**When** 購入希望者が「カートに追加」ボタンを1回押す、**Then** ボタン押下前に数量や配送先などの追加入力を求められることなく、当該書籍がカートに追加される。
3. **Given** 当該書籍が既にカートに数量1件以上入っている状態で商品詳細画面が表示されている、**When** 購入希望者が「カートに追加」ボタンを押す、**Then** 新しいカート項目は作られず、既存のカート項目の数量に1が加算される（[Clarifications Session 2026-09-09](#clarifications) 参照）。
4. **Given** 商品詳細画面が表示されている、**When** 購入希望者が「カートに追加」ボタンを押す、**Then** ボタンの表記が一時的に変化し（例:「追加しました」）、追加操作が成功したことを利用者が認識できる（[Clarifications Session 2026-09-09](#clarifications) 参照）。

---

### User Story 3 - カートに追加した後も一覧の閲覧を続ける (Priority: P1)

購入希望者として、商品詳細画面でカートに追加した後もそのまま商品一覧画面へ戻り、他の書籍を続けて閲覧できるようにしたい。これにより、複数冊をまとめて検討・購入できる。

**Why this priority**: 1冊ずつしか検討できないと複数冊のまとめ買いができず、購買体験が大きく損なわれる。要件定義書でも REQ-006 は優先度「高」。

**Independent Test**: 商品詳細画面でカートに追加した後、商品一覧へ戻る操作を行い、商品一覧画面が表示され、かつ直前に追加した書籍がカートに残っていることを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 商品詳細画面で書籍をカートに追加した、**When** 購入希望者が商品一覧へ戻る操作を行う、**Then** 商品一覧画面が表示され、直前にカートへ追加した書籍はカートに残ったままである。
2. **Given** 商品詳細画面が表示されている（カートに追加する前）、**When** 購入希望者が商品一覧へ戻る操作を行う、**Then** カートの内容を変更することなく商品一覧画面へ戻る。

---

### Edge Cases

- 書影が未設定の書籍は、全書籍共通のプレースホルダー画像を表示する（商品一覧画面と同一方針。User Story 1 参照）。
- 書籍データの取得に失敗した場合（通信エラー・サーバーエラー等）、商品一覧画面と同様の共通エラー表示（エラーメッセージのみ、再読み込み操作なし）を行う（[spec 004](../004-book-list-page/spec.md) の Clarifications 参照、本画面にも同一方針を適用）。
- 存在しない書籍ID（削除済み・不正なURL直接指定など）で商品詳細画面にアクセスした場合、商品一覧画面と同一の共通エラー表示を行う（専用の「見つかりません」画面は設けない。[Clarifications Session 2026-09-09](#clarifications) 参照）。
- 同一書籍を複数回「カートに追加」した場合、既存のカート項目の数量に1を加算する（新しい行は作らない。[Clarifications Session 2026-09-09](#clarifications) 参照）。
- 「カートに追加」ボタン押下時は、ボタンの表記を一時的に変化させて成功を伝える（専用の通知コンポーネントは設けない。[Clarifications Session 2026-09-09](#clarifications) 参照）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、商品詳細画面に当該書籍の書影・タイトル・著者・価格・説明文を表示しなければならない（REQ-004）。価格は税込み価格として1つの数値のみを表示し、税額や税抜き価格を別途表示しない（Clarifications Session 2026-09-09）。
- **FR-002**: システムは、商品詳細画面に「カートに追加」ボタンを表示し、押下操作のみで当該書籍をカートに追加できなければならない（数量入力等の追加操作を必須としない）（REQ-005）。連続クリック時のデバウンス等は行わず、クリックごとに独立した追加操作として扱う（Clarifications Session 2026-09-09）。
- **FR-003**: システムは、「カートに追加」ボタン押下によりカートに追加された書籍の数量を1件として計上しなければならない（REQ-005）。
- **FR-004**: システムは、商品詳細画面から商品一覧画面へ戻る導線（リンクまたはボタン）を提供しなければならない（REQ-006）。
- **FR-005**: システムは、商品詳細画面でカートに書籍を追加した後、購入希望者が商品一覧画面へ戻った際、追加済みの内容をカートに保持し続けなければならない（REQ-006）。
- **FR-006**: 商品詳細画面は未ログインの一般利用者が会員登録なしで閲覧できなければならない（要件定義書§2 対象範囲、ログイン・会員管理は対象外）。
- **FR-007**: システムは、書影が未設定の書籍について、全書籍共通のプレースホルダー画像を表示しなければならない（商品一覧画面と同一方針）。
- **FR-008**: システムは、書籍データの取得に失敗した場合、エラーメッセージを表示しなければならない（再読み込み操作の提供は不要。商品一覧画面と同一方針）。
- **FR-009**: システムは、存在しない書籍IDで商品詳細画面にアクセスされた場合、商品一覧画面と同一の共通エラー表示を行わなければならない（Clarifications Session 2026-09-09）。
- **FR-010**: システムは、同一書籍が既にカートに存在する状態で再度「カートに追加」が押下された場合、新しいカート項目を作らず、既存のカート項目の数量に1を加算しなければならない。この加算に数量の上限は設けない（Clarifications Session 2026-09-09）。
- **FR-011**: システムは、「カートに追加」ボタン押下が成功した際、ボタンの表記を一時的に変化させることで購入希望者に結果を伝えなければならない（Clarifications Session 2026-09-09）。

### Key Entities

- **書籍（Book）**: 販売対象の商品。本画面の表示に必要な属性として、識別子・書影・タイトル・著者・価格・説明文を持つ（説明文は商品一覧画面のスコープ外だが、本画面では表示対象）。価格は税込み価格の単一の数値として保持し、税抜き価格や税率は保持しない（Clarifications Session 2026-09-09）。
- **カート項目（CartItem）**: 購入希望者が購入予定の書籍を一時的に保持する単位。書籍への参照と数量を持つ。本画面からは「カートに追加」操作により数量1件分のカート項目が生成・更新される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 購入希望者は、商品詳細画面を開いた直後に、追加の操作なしで書影・タイトル・著者・価格・説明文の5項目すべてを視認できる。
- **SC-002**: 購入希望者が「カートに追加」ボタンを押してから、当該書籍がカートに反映されるまでに、ボタン押下以外の追加操作は一切発生しない。
- **SC-003**: 購入希望者は、商品詳細画面でカートに追加した後、商品一覧画面へ戻る操作1回で一覧の閲覧を再開でき、その時点でカート内の追加済み書籍が失われることはない（データ保持率100%）。
- **SC-004**: 同一書籍について「カートに追加」を複数回押した場合、カート内の当該書籍の項目は常に1行のまま保たれ、数量のみが押下回数分だけ増加する。
- **SC-005**: 購入希望者は、「カートに追加」ボタンを押した直後に、他の画面を確認することなくボタン上の表記変化から追加が成功したことを判別できる。

## Assumptions

- 「カートに追加」時の数量は常に1件から開始し、詳細画面上での数量指定（複数冊を一度に追加する操作）は行わない。数量の増減はカート画面（REQ-008）で行う。
- 商品詳細画面のレイアウト・デザインの詳細（書影の表示サイズ、説明文の折り返し等の具体仕様）は技術選定書に定めるCSS方針（CSS Modules）に従い、設計フェーズ（`/speckit.plan`）で具体化する。
- 読み込み中（ローディング）状態の表示有無・具体的な見た目は本仕様では規定せず、設計フェーズで憲法§3のUX一貫性方針に沿って具体化する。
- 検索・フィルター・レビュー・評価などは要件定義書§2で対象外と明記されている（本画面にも適用）。
