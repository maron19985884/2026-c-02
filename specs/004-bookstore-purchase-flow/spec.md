## User Scenarios & Testing *(mandatory)*

> 注記: 要件定義書では REQ-001〜REQ-018 のすべてが優先度「高」である。
> ここでの P1〜P4 は **購買導線上の依存順序（前段が成立しないと後段を検証できない）** による実装・検証の優先順位であり、
> 要件定義書の優先度を引き下げるものではない。

### User Story 1 - 販売中の書籍を探して内容を確かめる (Priority: P1)

サイトを訪れた購入希望者が、トップの商品一覧で販売中の書籍を一覧で眺め、気になった書籍をクリックして、その書籍の詳しい内容（説明文を含む）を確認する。

**Why this priority**: 購買導線の起点であり、これ単体でも「カタログを閲覧できる」という利用者価値が成立する。後続のすべてのストーリーが本ストーリーの画面を前提とする。

**Independent Test**: カート・注文機能が未実装でも、商品一覧に複数冊が表示され、任意の書籍をクリックして詳細画面に遷移し、書影・タイトル・著者・価格・説明文が読めることで独立に検証できる。

**Acceptance Scenarios**:

1. **Given** 販売中の書籍が複数登録されている, **When** 利用者が商品一覧画面を開く, **Then** 書籍がグリッド形式で複数冊まとめて表示され、各カードに書影・タイトル・著者・価格が表示される（REQ-001, REQ-002）
2. **Given** 商品一覧が表示されている, **When** 利用者が任意の書籍をクリックする, **Then** その書籍の商品詳細画面へ遷移する（REQ-003）
3. **Given** 商品詳細画面を開いている, **When** 画面を閲覧する, **Then** 当該書籍の書影・タイトル・著者・価格・説明文が表示される（REQ-004）
4. **Given** 販売中の書籍が1冊も登録されていない, **When** 利用者が商品一覧画面を開く, **Then** 空状態であることを示すメッセージが表示され、エラー画面にはならない
5. **Given** 販売中の書籍と販売停止の書籍が混在して登録されている, **When** 利用者が商品一覧画面を開く, **Then** 販売中の書籍のみが表示され、販売停止の書籍は表示されない（Clarification / FR-001a）
6. **Given** 販売中の書籍が全件表示されている, **When** 画面を確認する, **Then** ページ送りや追加読み込みの導線は存在せず、販売中の全書籍が1画面に並んでいる（Clarification / FR-001c）

### User Story 2 - 欲しい書籍をカートに入れて買い物を続ける (Priority: P2)

購入希望者が商品詳細画面から書籍をカートに追加し、そのまま商品一覧へ戻って他の書籍の閲覧・追加を続けられる。

**Why this priority**: 「複数冊をまとめて買う」という購買行動の中核。User Story 1 の画面が前提となる。

**Independent Test**: 注文フォーム・注文完了が未実装でも、詳細画面で「カートに追加」を押下 → 一覧へ戻る → 別の書籍を追加、という往復を行い、カートの保持件数が増えることで独立に検証できる。

**Acceptance Scenarios**:

1. **Given** 商品詳細画面を開いている, **When** 利用者が「カートに追加」ボタンを押す, **Then** 当該書籍がカートに追加され、追加されたことが利用者に分かる（REQ-005）
2. **Given** カートに追加した直後の商品詳細画面, **When** 利用者が「一覧へ戻る」導線を選ぶ, **Then** 商品一覧画面へ戻り、カートの内容は保持されたまま閲覧を続けられる（REQ-006）
3. **Given** いずれかの画面を開いている, **When** 利用者が共通ヘッダーのカート導線を選ぶ, **Then** カート画面へ遷移できる（要件定義書 §6 画面遷移 / FR-035）
3a. **Given** カートが0件の状態で商品詳細画面を開いている, **When** 利用者が「カートに追加」を押す, **Then** 共通ヘッダーのカート件数が0から1へ、画面遷移を伴わずに更新される（Clarification / FR-032, FR-034）
4. **Given** ある書籍が既にカートに数量1で入っている, **When** 利用者が同じ書籍の詳細画面で再度「カートに追加」を押す, **Then** カートの行は増えず、当該書籍の数量が2になる（Clarification Q3 / FR-009）
5. **Given** カートに書籍が入った状態でブラウザを閉じた, **When** 同じブラウザでサイトを再訪する, **Then** カートの内容（書籍と数量）が復元されている（Clarification Q1 / FR-016）

### User Story 3 - カートの中身を調整して合計金額を把握する (Priority: P3)

購入希望者がカート画面で、入れた書籍の書名・単価・数量・小計を確認し、数量の増減や不要な書籍の削除を行い、その都度更新される合計金額を見て購入内容を決める。

**Why this priority**: 注文確定の直前に「何をいくらで買うのか」を利用者が確定させる場。金額の正しさが購買の信頼性に直結する。

**Independent Test**: 注文フォームが未実装でも、カートに複数冊入れた状態から数量増減・削除を行い、小計・合計が期待値どおりに更新されることで独立に検証できる。

**Acceptance Scenarios**:

1. **Given** カートに1冊以上の書籍が入っている, **When** 利用者がカート画面を開く, **Then** 各書籍の書名・単価・数量・小計が一覧表示される（REQ-007）
2. **Given** カート画面を開いている, **When** 利用者がある書籍の数量を増やす／減らす, **Then** 当該書籍の小計とカートの合計金額が、画面遷移を伴わずその場で更新される（REQ-008）
3. **Given** カート画面に複数の書籍が入っている, **When** 利用者がある書籍を削除する, **Then** その行が一覧から消え、合計金額が即時に更新される（REQ-009）
4. **Given** カート画面を開いている, **When** 画面を閲覧する, **Then** カート内全書籍の小計の総和が合計金額として表示される（送料等は含まない）（REQ-010）
5. **Given** カートが0件である, **When** 利用者がカート画面を開く, **Then** カートが空であることを示すメッセージと商品一覧へ戻る導線が表示され、注文手続きへは進めない
6. **Given** カートに1冊以上の書籍が入っている, **When** 利用者が「注文手続きへ」ボタンを押す, **Then** 注文フォーム画面へ遷移する（REQ-011）
7. **Given** カート内のある書籍の数量が1である, **When** 利用者がその書籍の数量を減らして0にする, **Then** 当該書籍がカートから削除され、合計金額が即時に更新される（Clarification Q2 / FR-011a）
8. **Given** カートに書籍が1点だけ数量1で入っている, **When** 利用者がその数量を0にする, **Then** カートが0件となり、空状態の表示に切り替わって注文手続きへは進めない（FR-011a, FR-014）
9. **Given** カート画面を開いている, **When** 利用者が特定の書籍の数量を繰り返し増やす, **Then** 上限による拒否は発生せず、数量・小計・合計が増加し続ける（Clarification Q2 / FR-011b）
10. **Given** カートに書籍Aが数量2、書籍Bが数量3で入っている, **When** 利用者が任意の画面の共通ヘッダーを見る, **Then** カート件数として5（数量の合計）が表示される（Clarification / FR-033）

### User Story 4 - 注文情報を入力して注文を確定し、完了を確認する (Priority: P4)

購入希望者が注文フォームで氏名・住所・メールアドレスを入力し、同じ画面で注文内容と合計金額を確認したうえで「注文する」を押して注文を確定し、注文完了画面で注文番号を確認する。

**Why this priority**: 購買フローの終端であり、これが通って初めて「注文が完了できる」という要件全体の目的が達成される。User Story 1〜3 の成立が前提。

**Independent Test**: カートに書籍が入った状態から、未入力・形式不正でのエラー表示、正常入力での注文確定、注文完了画面の表示内容までを一連で検証できる。

**Acceptance Scenarios**:

1. **Given** 注文フォーム画面を開いている, **When** 画面を閲覧する, **Then** 氏名・住所・メールアドレスの入力欄と、注文対象の書籍および合計金額が**同一画面上**に表示される（REQ-012, REQ-014）
2. **Given** 注文フォーム画面を開いている, **When** 必須項目を未入力のまま「注文する」を押す, **Then** 未入力の項目が特定できるエラーメッセージが表示され、注文は確定されず注文完了画面へ遷移しない（REQ-013）
3. **Given** 注文フォーム画面を開いている, **When** メールアドレスに形式不正な値を入力して「注文する」を押す, **Then** 形式が不正である旨のエラーメッセージが表示され、注文は確定されない（REQ-013）
4. **Given** 氏名・住所・メールアドレスがすべて妥当に入力されている, **When** 利用者が「注文する」ボタンを押す, **Then** 注文が確定され、注文完了画面へ遷移する（REQ-015）
5. **Given** 注文が確定した, **When** 注文完了画面が表示される, **Then** 注文が受け付けられたことを示す完了メッセージ、注文を特定できる注文番号、商品一覧へ戻るリンクが表示される（REQ-016, REQ-017, REQ-018）
6. **Given** 注文完了画面を表示している, **When** 利用者が「商品一覧へ戻る」リンクを選ぶ, **Then** 商品一覧画面へ遷移する（REQ-018）
6a. **Given** 注文が確定して注文完了画面を表示している, **When** 利用者が商品一覧へ戻りカート画面を開く, **Then** カートは0件で空状態の表示となる（Clarification / FR-022a）
6b. **Given** 注文確定後にブラウザを閉じた, **When** 同じブラウザでサイトを再訪しカート画面を開く, **Then** 確定済みの注文内容は復元されず、カートは0件である（FR-022a）
6c. **Given** 注文の確定に失敗した, **When** 利用者がカート画面に戻る, **Then** カートの内容は失敗前のまま保持されている（FR-022b, FR-026）
6d. **Given** 注文完了画面を表示している, **When** 利用者が画面を再読込する, **Then** 注文番号を含む注文情報は表示されず、商品一覧への導線が示される（Clarification / FR-029a）
6e. **Given** 注文完了画面を表示している, **When** 画面のアドレスを確認する, **Then** アドレスに注文番号が含まれていない（FR-029b）
7. **Given** 注文が確定した, **When** 確定後の注文内容を参照する, **Then** 注文時点の書名・単価・数量・合計金額が注文の記録として保持されており、後から書籍の価格が変更されても注文記録の金額は変わらない

### Edge Cases

- **存在しない書籍の詳細を開いた場合**: 商品詳細画面で該当書籍が見つからないとき、利用者に「該当の書籍が見つかりません」と伝え、商品一覧へ戻る導線を示す。
- **カートが0件のまま注文フォームへ到達した場合**: 注文を確定させず、カートが空である旨とカート／商品一覧への導線を示す。
- **カートに入れた書籍が販売停止になった／削除された場合**: 注文確定時にその書籍が確定できない旨を利用者に伝え、注文全体を確定しない。
- **数量を0まで減らした場合**: 当該書籍はカートから自動的に削除され、合計金額が即時更新される。数量に上限は設けない。
- **再訪時に復元したカートの書籍が販売停止になっていた場合**: 復元時または注文手続きへの進行時にその旨を利用者に伝え、当該書籍を含んだままの注文確定を許さない。
- **販売停止の書籍の詳細ページへ直接アクセスされた場合**: 内容を表示せず、閲覧できない旨と商品一覧へ戻る導線を示す（存在しない書籍と同じ扱い）。
- **書影が用意されていない書籍**: レイアウトが崩れないよう代替表示を行い、タイトル・著者・価格の表示は維持する。
- **注文確定の処理に失敗した場合**: 注文完了画面へ遷移せず、注文が成立しなかったことを示すエラーメッセージを表示し、入力内容とカート内容を失わせない。
- **注文確定ボタンの二重押下**: 同一の注文が重複して確定されないようにする。
- **注文完了画面を再読込した場合**: 注文情報（注文番号を含む）を再表示せず、商品一覧への導線を示す。注文自体は確定済みのまま取り消されない。
- **一覧・詳細のデータ取得に失敗した場合**: 白画面にせず、取得に失敗した旨のエラー表示と再試行または一覧へ戻る導線を示す（憲法§3 のエラー表示統一）。

## Requirements *(mandatory)*

### Functional Requirements

**商品一覧（REQ-001〜REQ-003）**

- **FR-001**: システムは、販売中の書籍をグリッド形式で複数冊まとめて一覧表示しなければならない。（REQ-001）
- **FR-001a**: システムは、書籍が販売中か販売停止かを区別する状態を保持し、一覧・詳細のいずれにも販売中の書籍のみを表示しなければならない。（Clarification 2026-09-15）
- **FR-001b**: システムは、販売状態を変更する画面・操作を提供してはならない（管理画面はスコープ外）。販売状態は初期データとして与えられる。（Clarification 2026-09-15）
- **FR-001c**: システムは、販売中の書籍を件数で区切らず全件1画面に表示しなければならない。ページ送り・追加読み込みの導線は設けない。（Clarification 2026-09-15）
- **FR-001d**: システムは、一覧の表示順を一定の規則で固定し、同じデータに対して再読込しても並びが変わらないようにしなければならない。（表示順の規則は設計フェーズで決定）
- **FR-002**: システムは、一覧の各書籍について書影・タイトル・著者・価格を表示しなければならない。（REQ-002）
- **FR-003**: 利用者は、一覧上の書籍を選択することで、当該書籍の商品詳細へ遷移できなければならない。（REQ-003）
- **FR-004**: システムは、販売中の書籍が0件の場合、エラーではなく空状態であることを示す表示を行わなければならない。（憲法§3）

**商品詳細（REQ-004〜REQ-006）**

- **FR-005**: システムは、商品詳細において当該書籍の書影・タイトル・著者・価格・説明文を表示しなければならない。（REQ-004）
- **FR-005a**: システムは、販売停止の書籍の詳細が要求された場合、その内容を表示せず、該当の書籍を閲覧できない旨と商品一覧へ戻る導線を示さなければならない。（FR-001a）
- **FR-006**: 利用者は、商品詳細の「カートに追加」操作のみで（数量指定などの追加入力なしに）当該書籍をカートに追加できなければならない。（REQ-005）
- **FR-007**: システムは、カートへの追加が成立したことを、共通ヘッダーのカート件数の増加によって利用者に提示しなければならない。（REQ-005, FR-032）
- **FR-008**: 利用者は、カートに追加した後も商品一覧へ戻って閲覧を継続でき、その際カートの内容は保持されなければならない。（REQ-006）
- **FR-009**: システムは、既にカートに入っている書籍が再度追加された場合、新たな行を増やさず既存行の数量を1加算しなければならない。カート内に同一書籍の行は常に1行のみとする。（Clarification 2026-09-15）

**カート（REQ-007〜REQ-011）**

- **FR-010**: システムは、カート内の各書籍について書名・単価・数量・小計（単価 × 数量）を一覧表示しなければならない。（REQ-007）
- **FR-011**: 利用者は、カート内の各書籍の数量を増減でき、その結果が小計・合計へ即時に反映されなければならない。（REQ-008）
- **FR-011a**: システムは、数量が0になった書籍をカートから自動的に削除し、合計金額を即時更新しなければならない。（Clarification 2026-09-15）
- **FR-011b**: システムは、数量の上限を設けてはならない。在庫管理をスコープ外とするため、在庫に基づく数量制限も行わない。（Clarification 2026-09-15）
- **FR-012**: 利用者は、数量の増減とは別に、カートから書籍を明示的に削除でき、削除後に合計金額が即時更新されなければならない。（REQ-009）
- **FR-013**: システムは、カート内全書籍の小計の総和を合計金額として表示しなければならない。送料・手数料・割引は算入しない。（REQ-010、スコープ外機能）
- **FR-014**: システムは、カートが0件の場合、空状態であることを示す表示と商品一覧への導線を示し、注文手続きへの進行を許してはならない。（憲法§3）
- **FR-015**: 利用者は、カートに1冊以上の書籍がある状態で「注文手続きへ」を選ぶことで注文フォームへ遷移できなければならない。（REQ-011）
- **FR-016**: システムは、カート内容を同一ブラウザにおいて永続的に保持し、タブやブラウザを閉じて再訪した場合にも復元しなければならない。（Clarification 2026-09-15）
- **FR-016a**: システムは、カートを端末・ブラウザを跨いで引き継いではならない（会員機能を持たないため）。（Clarification 2026-09-15）
- **FR-016b**: システムは、復元したカートに販売停止となった書籍または削除された書籍が含まれる場合、その旨を利用者に提示し、当該書籍を含んだまま注文を確定させてはならない。（FR-001a）

**注文フォーム（REQ-012〜REQ-015）**

- **FR-017**: 利用者は、注文フォームで氏名・住所・メールアドレスを入力できなければならない。この3項目はすべて必須とする。（REQ-012）
- **FR-018**: システムは、必須項目が未入力の場合、どの項目が未入力かを特定できるエラーメッセージを表示しなければならない。（REQ-013）
- **FR-019**: システムは、メールアドレスが形式として妥当でない場合、形式不正である旨のエラーメッセージを表示しなければならない。（REQ-013）
- **FR-020**: システムは、バリデーションエラーがある間、注文を確定させてはならず、入力済みの内容を失わせてはならない。（REQ-013）
- **FR-021**: システムは、注文フォームと同一画面上に注文対象の書籍と合計金額を表示しなければならない（別の確認画面を挟まない）。（REQ-014）
- **FR-022**: 利用者は、妥当な入力の状態で「注文する」を1回操作することで注文を確定し、注文完了画面へ遷移できなければならない。（REQ-015）
- **FR-022a**: システムは、注文が確定した時点でカートを空にし、同一ブラウザでの復元対象データも破棄しなければならない。注文完了画面から商品一覧へ戻った後も、再訪した後も、確定済みの注文内容がカートに残ってはならない。（Clarification 2026-09-15）
- **FR-022b**: システムは、注文の確定が成立しなかった場合はカートを空にしてはならない（FR-026 と整合）。（Clarification 2026-09-15）
- **FR-023**: システムは、注文確定時に注文番号を発行し、注文を一意に特定できるようにしなければならない。（REQ-017）
- **FR-024**: システムは、注文確定時点の書名・単価・数量・合計金額を注文の記録として保持し、以後の書籍情報の変更によって注文記録の内容が変化しないようにしなければならない。
- **FR-025**: システムは、同一の注文確定操作が重複して受け付けられないようにしなければならない。
- **FR-026**: システムは、注文の確定に失敗した場合、注文完了画面へ遷移せず、失敗した旨を利用者に提示しなければならない。

**注文完了（REQ-016〜REQ-018）**

- **FR-027**: システムは、注文完了画面に注文が受け付けられたことを示す完了メッセージを表示しなければならない。（REQ-016）
- **FR-028**: システムは、注文完了画面に発行された注文番号を表示しなければならない。（REQ-017）
- **FR-029**: 利用者は、注文完了画面から商品一覧へ戻るリンクを選べなければならない。（REQ-018）
- **FR-029a**: システムは、注文完了の内容を直前に確定した注文に対してのみ表示しなければならない。注文完了画面の再読込、ブックマークや履歴からの再訪、直接アクセスの場合は、注文番号を含む注文情報を表示せず、商品一覧への導線を示さなければならない。（Clarification 2026-09-15）
- **FR-029b**: システムは、注文を特定できる情報（注文番号）を画面のアドレスに含めてはならない。会員機能を持たず閲覧者を識別できないため、アドレスの書き換えによって他者の注文情報が閲覧可能になってはならない。（Clarification 2026-09-15）
- **FR-029c**: システムは、注文番号が再表示できない旨を注文完了画面上で利用者に伝え、控えるよう促さなければならない。（FR-029a の帰結）

**全画面共通**

- **FR-030**: システムは、エラー表示・空状態表示・画面遷移の扱いを全画面で統一しなければならない。（憲法§3）
- **FR-032**: システムは、全画面に共通のヘッダーを設け、カート画面への導線とカート内の件数を常時表示しなければならない。（Clarification 2026-09-15）
- **FR-033**: システムが表示するカート件数は、カート内全書籍の**数量の合計**とする（行数ではない）。カートが0件のときは0または件数なしと分かる表示にする。（Clarification 2026-09-15）
- **FR-034**: システムは、カートの内容が変化した時点（追加・数量増減・削除・注文確定によるクリア）で、ヘッダーの件数表示を画面遷移を伴わずに更新しなければならない。（Clarification 2026-09-15）
- **FR-035**: 利用者は、共通ヘッダーのカート導線から、どの画面からでもカート画面へ遷移できなければならない。（要件定義書 §6 画面遷移）
- **FR-031**: システムは、ログイン・会員登録・決済・在庫管理・管理画面・レビュー・検索／フィルター・送料計算のいずれも提供してはならない。（requirements.md §2 対象外）

### Key Entities *(include if feature involves data)*

- **書籍（Book）**: 販売対象の商品。書影、タイトル、著者、価格、説明文、**販売状態（販売中／販売停止）** を持ち、一意に識別できる。商品一覧・商品詳細には販売中のもののみを表示する。販売状態は初期データとして与えられ、本フィーチャーからは変更しない（FR-001a, FR-001b）。
- **カート（Cart）**: 一人の利用者が購入予定として保持する書籍と数量の集合。0件以上のカート明細を持ち、合計金額を導出できる。同一ブラウザ内で永続的に保持され、端末・ブラウザを跨いだ共有は行わない（FR-016, FR-016a）。
- **カート明細（Cart Item）**: カート内の1書籍分の情報。対象書籍、数量を持ち、小計（単価 × 数量）を導出する。同一書籍につき常に1行とし、数量が0になった時点でカートから取り除かれる（FR-009, FR-011a）。
- **注文（Order）**: 確定した購買の記録。注文番号、注文時点の合計金額、注文日時、顧客情報を持ち、1件以上の注文明細を持つ。
- **注文明細（Order Item）**: 注文に含まれる1書籍分の確定内容。注文時点の書名・単価・数量・小計を保持する（書籍情報の後の変更に影響されない）。
- **顧客情報（Customer Info）**: 注文に紐づく氏名・住所・メールアドレス。会員情報としては扱わず、注文単位の情報として保持する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めて訪れた利用者が、事前説明なしに商品一覧から注文完了までの購買フローを最後まで完了できる（会員登録・決済入力を求められることなく、氏名・住所・メールアドレスの3項目入力のみで完了する）。
- **SC-002**: 商品一覧・商品詳細・カート・注文フォーム・注文完了の5画面すべてについて、要件定義書 §8 の受け入れ基準13項目が受け入れテストですべて合格する（REQ-001〜REQ-018 の網羅率100%）。
- **SC-003**: カート内の数量変更・書籍削除を行ったとき、小計と合計金額が画面遷移を伴わずに更新され、表示値が「各書籍の単価 × 数量」の総和と一致する（任意の組み合わせで検算して不一致0件）。
- **SC-004**: 氏名・住所・メールアドレスについて、未入力および形式不正の各パターンで注文が確定せずエラーメッセージが表示される（バリデーション回避による注文確定0件）。
- **SC-005**: 注文完了画面に表示される注文番号が、確定した注文と1対1で対応し、複数回の注文で重複しない（重複0件）。
- **SC-006**: 注文確定後に書籍の価格が変更されても、確定済み注文の明細金額および合計金額が変化しない。
- **SC-007**: 主要画面の表示および操作への応答が、95パーセンタイルで2秒以内に完了する（憲法§4 の暫定基準）。
- **SC-008**: 主要なビジネスロジック（合計金額の算出、入力バリデーション、注文番号の発行）について単体テストが用意され、カバレッジ80%以上を満たす（憲法§2、requirements.md §4 保守性）。
- **SC-009**: 全画面で、エラー表示・空状態表示の見え方と文言の方針が統一されている（画面ごとの不統一0件）。
- **SC-010**: カートに書籍を入れてブラウザを閉じ、同じブラウザで再訪したとき、カートの書籍と数量が閉じる前と一致する（復元失敗0件）。（Clarification Q1）
- **SC-011**: 同一書籍を n 回「カートに追加」したとき、カート内の当該書籍は常に1行で、数量が n と一致する（重複行0件）。（Clarification Q3）
- **SC-012**: 注文確定の成功後、同一ブラウザでの再訪を含めてカートが0件であり、確定済み注文の商品がカートへ残存しない（残存0件）。注文確定の失敗時はカート内容が保持される。
- **SC-013**: 注文完了画面の再読込・直接アクセスによって他者または過去の注文情報が表示される経路が存在しない（注文情報の露出0件）。注文番号がアドレスに現れる箇所0件。（Clarification）
- **SC-014**: 5画面すべてにカートへの導線と件数が表示され、表示件数がカート内の数量合計と常に一致する（不一致0件）。（Clarification / FR-032, FR-033）
- **SC-015**: 商品一覧に表示される書籍数が、販売中として登録されている書籍数と一致する（欠落0件・販売停止の混入0件）。（Clarification / FR-001a, FR-001c）

## Assumptions

以下は要件定義書に明記がないため、本仕様で置いた前提である。誤りがあれば `/speckit.clarify` または変更要求で是正する。

- **利用者**: 未ログインの一般利用者のみを想定し、利用者を識別する仕組み（会員ID等）は持たない。利用者ごとのカートはブラウザ単位で分離される。
- **注文確定後のカート**: 要件化済み（FR-022a / FR-022b）。注文確定の成功時のみカートを空にし、失敗時は保持する。
- **価格表示**: 価格は日本円の単一通貨で、税込価格をそのまま表示・合計する。税額の内訳表示・税計算・割引・送料は行わない（requirements.md §2 対象外）。
- **注文番号**: 利用者が問い合わせ時に伝達できる、注文を一意に特定する文字列とする。採番方式は設計フェーズ（`/speckit.plan`）で決定する。
- **バリデーションのタイミング**: エラーメッセージは少なくとも「注文する」操作時に表示する。入力中のリアルタイム検証を追加するかは設計判断に委ねる。
- **メールアドレスの妥当性**: 形式（ローカル部・@・ドメイン部の構造）の検証にとどめ、実在確認・到達確認は行わない（外部サービス連携はスコープ外）。
- **書籍データ**: 書籍はあらかじめ用意されたデータとして存在し、本フィーチャーは書籍の登録・編集・削除および販売状態の変更を提供しない（管理画面はスコープ外）。検証のために販売停止の書籍を初期データへ含めておく必要がある。
- **書籍の規模**: 学習・デモ用途のため、初期データの書籍数は全件を1画面に表示しても性能基準（SC-007）を満たせる規模（十数冊程度）を前提とする。大量データでの一覧表示は想定しない（FR-001c）。
- **在庫**: 在庫管理はスコープ外のため、数量に対する在庫上限の制約は設けない（FR-011b と整合）。
- **カートの保持期間**: カートの復元に有効期限は設けない（要件定義書に期限の定めがなく、注文確定時にクリアされるため FR-022a で滞留しない）。利用者がブラウザのデータを消去した場合は復元されない。
- **メール送信**: 注文完了時の確認メール送信は行わない（外部サービス連携はスコープ外）。メールアドレスは注文情報として保持するのみ。
- **注文履歴の閲覧**: 確定後に注文内容を再度参照する手段（注文履歴・注文照会画面）は提供しない。要件定義書 REQ-016〜REQ-018 に定めがなく、会員機能を持たないため閲覧者を本人と確認できないことによる（FR-029a）。
- **利用環境**: ローカル環境での単一利用者による動作を前提とし、同時注文の競合制御は考慮しない（requirements.md §4 可用性）。
- **アクセシビリティ**: WCAG 2.1 AA を目標とする（憲法§3）。具体的な達成手段は設計フェーズで扱う。
