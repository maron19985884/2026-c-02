詳細設計書：個人運営オンライン書店（購買フロー特化版）

作成日: 2026-08-05 ／ 対応: plan.md / data-model.md / contracts/ ／ 憲法（.specify/memory/constitution.md 7章）に基づきHTMLで作成（パラメータ・修正対象ファイル・処理概要・In/Out）

1. API GET /api/books（商品一覧取得）

修正/新規対象ファイルbackend/src/api/books.ts（新規）／backend/src/services/bookService.ts（新規）
パラメータなし
処理概要booksテーブルを全件SELECTし、一覧表示に必要な列（id, title, author, price, image_url）のみ抽出して返却する。descriptionは一覧では返さない。
Inなし
Out200: Book[]（contracts/books-api.md参照）

2. API GET /api/books/:id（商品詳細取得）

修正/新規対象ファイルbackend/src/api/books.ts／backend/src/services/bookService.ts
パラメータid（pathパラメータ, number, 必須）
処理概要booksテーブルをidでSELECT。該当行がなければ404を返す。
Inid: number
Out200: 書籍詳細（id, title, author, price, description, imageUrl）／404: { error: "BOOK_NOT_FOUND" }

3. API POST /api/orders（注文確定）

修正/新規対象ファイル backend/src/api/orders.ts（新規）／ backend/src/services/orderService.ts（新規）／ backend/src/services/orderValidation.ts（新規）／ backend/src/services/orderNumber.ts（新規）
パラメータ リクエストボディ: customerName: string（必須）, address: string（必須）, email: string（必須・メール形式）, items: { bookId: number, quantity: number }[]（1件以上必須）
処理概要 ①orderValidation.tsで必須・形式・items非空を検証（不正なら400）→ ②各bookIdがbooksテーブルに存在するか確認（存在しなければ404）→ ③書籍の現在価格から明細ごとの小計・合計金額を算出→ ④orderNumber.tsでORD-YYYYMMDD-NNNN形式の注文番号を採番→ ⑤orders・order_itemsへトランザクションでINSERT（書籍タイトル・単価はスナップショットとして複製）→ ⑥登録結果を返却
InOrderRequest（contracts/orders-api.md参照）
Out201: OrderResponse（orderNumber, createdAt, items, totalAmount）／400: VALIDATION_ERROR／404: BOOK_NOT_FOUND

4. フロントエンド カート状態管理（CartContext）

修正/新規対象ファイルfrontend/src/contexts/CartContext.tsx（新規）
パラメータ／公開関数 addItem(bookId, book)／ increaseQuantity(bookId)／ decreaseQuantity(bookId)／ removeItem(bookId)
処理概要 addItem: 既存のbookIdがあれば数量+1、なければ新規追加（FR-021）。 decreaseQuantity: 数量1のときは何もしない（下限1。FR-022）。 変更のたびにtotalAmount（全明細のprice * quantityの合計）を再計算する。
InbookId, 数量変更操作
OutContext経由でカート画面・注文フォーム画面に渡すitems[]・totalAmount

5. フロントエンド 注文フォームバリデーション

修正/新規対象ファイルfrontend/src/components/OrderForm.tsx（新規）／frontend/src/services/validation.ts（新規）
パラメータcustomerName: string, address: string, email: string
処理概要 「注文する」押下時に3項目の必須チェックとメールアドレスの形式チェック（正規表現 ^[^\s@]+@[^\s@]+\.[^\s@]+$）をクライアント側で行い、 不正があれば該当項目にエラーメッセージを表示して送信しない（FR-013）。 すべて正しい場合のみPOST /api/ordersを呼び出す。
Inフォーム入力値
Outフィールドごとのエラーメッセージ有無、またはAPI呼び出し結果に基づく画面遷移
