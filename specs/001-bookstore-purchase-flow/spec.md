# Feature Specification: 個人運営オンライン書店（購買フロー特化版）

**Feature Branch**: `001-bookstore-purchase-flow`

**Created**: 2026-08-05

**Status**: Draft

**Input**: User description: "user_requirements.md の内容に基づいて、個人運営オンライン書店（購買フロー特化版）の仕様化を行う。対象は商品一覧・商品詳細・カート・注文フォーム・注文完了の5画面、U-01〜U-18。ログイン・会員管理／決済処理／在庫管理／管理画面／レビュー・評価／検索・フィルターはスコープ外。"

## Clarifications

### Session 2026-08-05

- Q: カートが空の状態でも「注文手続きに進む」導線を表示してよいか？ → A: 非表示。カートに1件以上ある場合のみ表示する。
- Q: 同じ書籍を詳細画面から何度も「カートに追加」した場合、カート内での挙動は？ → A: 数量を加算する（別行にはしない）。
- Q: カート内の数量が1の状態でさらに減らす操作をしたらどうなるか？ → A: 1未満にはできない。減らす操作は数量1で非活性化し、削除は別の削除操作で行う。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 商品を探してカートに入れる (Priority: P1)

書店サイトを訪れた購入希望者が、販売中の書籍をグリッド形式で一覧から見つけ、気になる本の詳細（書影・タイトル・著者・価格・説明文）を確認し、購入意思が固まった本を「カートに追加」ボタン1つでカートに入れる。追加後も一覧に戻って他の本を見続けられる。

**Why this priority**: これがなければ何も始まらない、購買フローの起点。単独でも「本を探して選ぶ」という価値を提供できる。

**Independent Test**: 商品一覧画面を開き、任意の商品をクリックして詳細画面へ遷移し、「カートに追加」を押してカートに商品が入ること、かつ一覧画面に戻れることを確認すれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 商品一覧画面を開いている、**When** 販売中の書籍が複数冊存在する、**Then** 書影・タイトル・著者・価格を含むグリッド形式で一覧表示される
2. **Given** 商品一覧画面で気になる本を見つけた、**When** その本をクリックする、**Then** 書影・タイトル・著者・価格・説明文を含む商品詳細画面に遷移する
3. **Given** 商品詳細画面を開いている、**When** 「カートに追加」ボタンを押す、**Then** その本がカートに追加され、商品一覧画面に戻って他の本を見続けられる

---

### User Story 2 - カートの中身を確認・調整する (Priority: P2)

カートに入れた本の一覧（書名・単価・数量・小計）を確認し、数量を増減させたり不要な本を削除したりして、合計金額をリアルタイムに確認しながら注文内容を整える。

**Why this priority**: カートに入れた後、注文に進む前に内容を確定させる工程であり、User Story 1で商品が追加されていることを前提に独立して検証できる。

**Independent Test**: 商品が1件以上入ったカート画面を開き、数量変更・削除操作それぞれで小計・合計金額が即時更新されることを確認すれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** カートに1件以上の本が入っている、**When** カート画面を開く、**Then** 各本の書名・単価・数量・小計と、全体の合計金額が表示される
2. **Given** カート画面を開いている、**When** ある本の数量を増減させる、**Then** その本の小計と全体の合計金額がリアルタイムに更新される
3. **Given** ある本の数量が1になっている、**When** さらに数量を減らそうとする、**Then** 数量は1未満にならず、減らす操作は非活性化される（削除は別の削除操作で行う）
4. **Given** カート画面を開いている、**When** ある本を削除する、**Then** カートからその本が消え、合計金額が即時更新される
5. **Given** カートに1件以上の本が入っている、**When** 「注文手続きに進む」を選ぶ、**Then** 注文フォーム画面に遷移する
6. **Given** カートが空である、**When** カート画面を開く、**Then** 「注文手続きに進む」導線は表示されない

---

### User Story 3 - 注文情報を入力して確定する (Priority: P3)

カートの内容と合計金額を見ながら、氏名・住所・メールアドレスを入力し、入力ミスがあればその場でエラーに気づき、修正した上で注文を確定する。

**Why this priority**: 注文確定というビジネス上の成果に直結する工程。カートの内容（User Story 2）が固まっていることを前提とする。

**Independent Test**: カート内容がある状態で注文フォーム画面を開き、必須項目の未入力・形式不正でエラー表示されること、正しく入力すると「注文する」で次画面に進めることを確認すれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 注文フォーム画面を開いている、**When** 画面を表示する、**Then** カートに入れた商品と合計金額が同画面で確認できる
2. **Given** 注文フォーム画面で氏名・住所・メールアドレスのいずれかが未入力、**When** 「注文する」を押す、**Then** 未入力項目についてエラーメッセージが表示され、注文は確定しない
3. **Given** メールアドレス欄に形式不正な値が入力されている、**When** 「注文する」を押す、**Then** 形式不正であることを示すエラーメッセージが表示され、注文は確定しない
4. **Given** 氏名・住所・メールアドレスすべてが正しく入力されている、**When** 「注文する」を押す、**Then** 注文が確定し、注文完了画面に遷移する

---

### User Story 4 - 注文完了を確認する (Priority: P4)

注文確定後、注文が受け付けられたことと自分の注文を特定できる注文番号を確認し、必要であれば商品一覧に戻ってサイトの利用を続けられる。

**Why this priority**: 購買フローの締めくくりであり、ユーザーに安心感を与える工程。User Story 3で注文が確定していることを前提とする。

**Independent Test**: 注文確定直後の状態で注文完了画面を開き、完了メッセージと注文番号が表示されること、一覧に戻るリンクで商品一覧画面に遷移できることを確認すれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 注文フォームで注文を確定した、**When** 注文完了画面が表示される、**Then** 注文が受け付けられたことを示すメッセージが表示される
2. **Given** 注文完了画面を開いている、**When** 画面を確認する、**Then** その注文を特定できる注文番号が表示される
3. **Given** 注文完了画面を開いている、**When** 「商品一覧へ戻る」リンクを押す、**Then** 商品一覧画面に遷移する

---

### Edge Cases

- カートが空の状態では「注文手続きに進む」導線を表示しない（Clarifications参照）
- 同じ本を複数回「カートに追加」した場合はカート内で数量を加算する（Clarifications参照）
- カート内の数量が1の状態でさらに減らす操作は非活性化し、1未満にはならない（Clarifications参照）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは販売中の書籍をグリッド形式で一覧表示しなければならない（U-01）
- **FR-002**: システムは商品一覧の各書籍について書影・タイトル・著者・価格を表示しなければならない（U-02）
- **FR-003**: ユーザーは商品一覧から任意の書籍をクリックして商品詳細画面に遷移できなければならない（U-03）
- **FR-004**: システムは商品詳細画面に書影・タイトル・著者・価格・説明文を表示しなければならない（U-04）
- **FR-005**: ユーザーは商品詳細画面の「カートに追加」ボタン1つで、その書籍をカートに追加できなければならない（U-05）
- **FR-006**: システムはカートに追加した後も商品一覧画面へ戻れるようにしなければならない（U-06）
- **FR-007**: システムはカート画面にカート内の各書籍の書名・単価・数量・小計を表示しなければならない（U-07）
- **FR-008**: ユーザーはカート内の書籍の数量を増減でき、変更に応じて小計と合計金額がリアルタイムに更新されなければならない（U-08）
- **FR-009**: ユーザーはカートから不要な書籍を削除でき、削除後は合計金額が即時更新されなければならない（U-09）
- **FR-010**: システムはカート内の全商品の合計金額を表示しなければならない（送料等の表示は対象外）（U-10）
- **FR-011**: ユーザーはカート画面から注文フォーム画面へ遷移できなければならない（U-11）
- **FR-012**: システムは注文フォームで氏名・住所・メールアドレスの入力を受け付け、3項目すべてを必須項目としなければならない（U-12）
- **FR-013**: システムは氏名・住所・メールアドレスについて、未入力または形式不正の場合にエラーメッセージを表示しなければならない（U-13）
- **FR-014**: システムは注文フォーム画面でカートの注文商品と合計金額を同画面に表示しなければならない（U-14）
- **FR-015**: ユーザーは入力完了後、「注文する」ボタン1つで注文を確定し、注文完了画面に進めなければならない（U-15）
- **FR-016**: システムは注文完了画面に注文受付を示すメッセージを表示しなければならない（U-16）
- **FR-017**: システムは注文完了画面に、その注文を特定できる注文番号を表示しなければならない（U-17）
- **FR-018**: システムは注文完了画面に商品一覧へ戻るリンクを表示しなければならない（U-18）
- **FR-019**: システムはログイン・会員管理、決済処理、在庫管理、管理画面、レビュー・評価、検索・フィルターの各機能を提供してはならない（スコープ外の明示的除外）
- **FR-020**: システムはカートが空の場合、「注文手続きに進む」導線を表示してはならない（カートに1件以上ある場合のみ表示する）
- **FR-021**: システムは同じ書籍が複数回カートに追加された場合、カート内で別行を作らず数量を加算しなければならない
- **FR-022**: システムはカート内の書籍の数量下限を1とし、1の状態からさらに減らす操作を行えないようにしなければならない（不要な場合は削除操作を用いる）

### Key Entities *(include if feature involves data)*

- **書籍（Book）**: 販売対象の本。書影、タイトル、著者、価格、説明文を持つ。商品一覧・商品詳細・カート・注文フォームで参照される。
- **カート（Cart）**: 購入希望者が選んだ書籍とその数量の集合。書籍ごとの小計と、カート全体の合計金額を持つ。
- **カート明細（CartItem）**: カートに含まれる1書籍分の明細。書籍への参照と数量を持ち、単価×数量で小計を算出する。
- **注文（Order）**: 確定した注文内容。注文者の氏名・住所・メールアドレス、注文時点のカート内容（書籍・数量・小計）、合計金額、一意な注文番号を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は商品一覧を開いてから任意の商品をカートに追加するまで、画面遷移2回以内（一覧→詳細→カート追加）で完了できる
- **SC-002**: カート画面での数量変更・削除操作は、画面の再読み込みなしに1秒以内に小計・合計金額へ反映される
- **SC-003**: 注文フォームで必須項目の未入力・形式不正がある場合、100%のケースで送信前にエラーメッセージが提示され、不正な注文が確定しない
- **SC-004**: 確定した注文には必ず一意な注文番号が発行され、注文完了画面に表示される
- **SC-005**: 初めて訪れた利用者が商品一覧→商品詳細→カート→注文フォーム→注文完了まで、他の案内なしに操作を完了できる

## Assumptions

- 注文番号は注文ごとに一意であればよく、生成方式（連番／UUID等）は詳細設計フェーズ（`/speckit-plan`）で確定する
- 送料・税額の計算・表示ルールは、ユーザー要件定義書（`user_requirements.md`）の記載どおりスコープ外とする
- メールアドレスの形式チェックは、一般的なメールアドレス形式（`local-part@domain`）の検証で十分とする
