# Feature Specification: 商品一覧画面

**Feature Branch**: `004-book-list-page`
**Created**: 2026-09-09
**Status**: Draft
**Input**: User description: "商品一覧画面: 販売中の書籍をグリッド形式で一覧表示し、各書籍の書影・タイトル・著者・価格を表示する。書籍をクリックすると商品詳細画面へ遷移する。(REQ-001, REQ-002, REQ-003)"

## Clarifications

### Session 2026-09-09

- Q: 商品一覧画面で書籍を並べる順序はどうしますか？（要件定義書に並び順の指定なし） → A: 登録順（ID昇順）
- Q: 書籍データの取得に失敗（通信エラー・サーバーエラー等）した場合、商品一覧画面はどう振る舞うべきですか？ → A: 共通エラー表示（再読み込みなし。エラーメッセージのみ表示し、再試行操作は提供しない）
- Q: 書影（カバー画像）が未設定の書籍が一覧にあった場合、代替表示はどうしますか？ → A: 共通プレースホルダー画像（全書籍共通の固定画像を表示する）
- Q: 書籍件数が多い場合、商品一覧画面は全件を一度に表示しますか、それともページ分割（または無限スクロール）を行いますか？ → A: 常に全件表示（ページ分割なし）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 販売中の書籍をまとめて見る (Priority: P1)

書店サイトを訪れた購入希望者として、販売中の書籍をグリッド形式でまとめて一覧表示できるようにしたい。これにより、どんな書籍があるかを一度に把握し、目当ての本を探し始められる。

**Why this priority**: 一覧表示は購買フロー（一覧 → 詳細 → カート → 注文フォーム → 注文完了）の起点であり、これがなければ他のどの画面にも到達できない。要件定義書でも REQ-001 は優先度「高」。

**Independent Test**: 書籍データが1件以上存在する状態で商品一覧画面を開き、グリッド形式で複数冊が表示されることを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 販売中の書籍が複数件登録されている、**When** 購入希望者が商品一覧画面を開く、**Then** 販売中の書籍がグリッド形式で複数冊まとめて表示される。
2. **Given** 販売中の書籍が1件も登録されていない、**When** 購入希望者が商品一覧画面を開く、**Then** 書籍が0件であることを示す空状態の表示がなされる（憲法§3のUX一貫性に基づき、他画面の空状態表示と統一された扱いとする）。

---

### User Story 2 - 一覧上で書籍の基本情報を確認する (Priority: P1)

購入希望者として、一覧の各書籍カード上で書影・タイトル・著者・価格を確認できるようにしたい。これにより、詳細画面を開かなくても候補を絞り込める。

**Why this priority**: 一覧表示（User Story 1）と対になる基本要件であり、情報が無ければ一覧表示自体の価値がない。要件定義書でも REQ-002 は優先度「高」。

**Independent Test**: 商品一覧画面を開き、各書籍カードに書影・タイトル・著者・価格の4項目が表示されていることを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 商品一覧画面が表示されている、**When** 購入希望者が任意の書籍カードを見る、**Then** その書籍の書影・タイトル・著者・価格が表示されている。
2. **Given** ある書籍に書影データが設定されていない、**When** その書籍が一覧に表示される、**Then** 書影の代わりに全書籍共通のプレースホルダー画像が表示され、タイトル・著者・価格は通常どおり表示される（[Clarifications Session 2026-09-09](#clarifications) 参照）。

---

### User Story 3 - 一覧から詳細画面へ遷移する (Priority: P1)

購入希望者として、一覧の書籍をクリックすると、その書籍の商品詳細画面に遷移できるようにしたい。これにより、気になった書籍についてより詳しい情報（説明文など）を確認できる。

**Why this priority**: 一覧から詳細への遷移は購買フローを先に進めるための唯一の導線であり、これがないと一覧表示の情報だけで購入判断を迫られてしまう。要件定義書でも REQ-003 は優先度「高」。

**Independent Test**: 商品一覧画面で任意の書籍をクリックし、その書籍に対応する商品詳細画面へ遷移することを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 商品一覧画面が表示されている、**When** 購入希望者が特定の書籍カードをクリックする、**Then** クリックした書籍の商品詳細画面へ遷移する。
2. **Given** 一覧に複数の書籍が表示されている、**When** 購入希望者が異なる書籍カードをクリックする、**Then** それぞれクリックした書籍に対応する詳細画面へ正しく遷移する（別の書籍の詳細に遷移しない）。

---

### Edge Cases

- 販売中の書籍が0件の場合、一覧はどう表示されるか？（→ User Story 1 の空状態表示で対応）
- 書籍データの取得に失敗した場合（通信エラー・サーバーエラー等）、一覧画面は共通エラー表示（エラーメッセージのみ、再読み込み操作なし）を行う（[Clarifications Session 2026-09-09](#clarifications) 参照）。
- 書籍データの件数が多い場合、一覧は常に全件を一度に表示する（ページ分割・無限スクロールは行わない。[Clarifications Session 2026-09-09](#clarifications) 参照）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、販売中の書籍をグリッド形式で複数冊まとめて表示しなければならない（REQ-001）。
- **FR-002**: システムは、一覧の各書籍について書影・タイトル・著者・価格を表示しなければならない（REQ-002）。
- **FR-003**: システムは、購入希望者が一覧上の書籍をクリックした際、その書籍に対応する商品詳細画面へ遷移させなければならない（REQ-003）。
- **FR-004**: システムは、販売中の書籍が0件の場合、書籍が存在しないことを示す空状態を表示しなければならない（憲法§3 UX一貫性）。
- **FR-005**: 商品一覧画面は未ログインの一般利用者が会員登録なしで閲覧できなければならない（要件定義書§2 対象範囲、ログイン・会員管理は対象外）。
- **FR-006**: システムは、一覧の書籍を登録順（ID昇順）で表示しなければならない（Clarifications Session 2026-09-09）。
- **FR-007**: システムは、書籍データの取得に失敗した場合、エラーメッセージを表示しなければならない（再読み込み操作の提供は不要。Clarifications Session 2026-09-09）。
- **FR-008**: システムは、書影が未設定の書籍について、全書籍共通のプレースホルダー画像を表示しなければならない（Clarifications Session 2026-09-09）。
- **FR-009**: システムは、書籍件数によらず一覧の全件を一度に表示しなければならない（ページ分割・無限スクロールは行わない。Clarifications Session 2026-09-09）。

### Key Entities

- **書籍（Book）**: 販売対象の商品。一覧表示に必要な属性として、識別子・書影・タイトル・著者・価格を持つ（説明文は商品詳細画面でのみ使用するため本機能のスコープ外）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 販売中の書籍が1件以上存在する状態で商品一覧画面を開いたとき、購入希望者は画面を開いた直後に、追加の操作なしで複数冊の書籍をグリッド形式で視認できる。
- **SC-002**: 購入希望者は、一覧上のいずれの書籍についても、書影・タイトル・著者・価格の4項目すべてを他の画面へ移動することなく確認できる。
- **SC-003**: 購入希望者が一覧上の任意の書籍をクリックしてから、その書籍の商品詳細画面が表示されるまでの間、目的の書籍以外の詳細画面が表示されることはない（遷移先の正確性100%）。
- **SC-004**: 販売中の書籍が0件のとき、購入希望者は一覧画面が正常に読み込まれた状態であること（エラーではないこと）を、空状態の表示から判別できる。

## Assumptions

- 「販売中の書籍」とは、要件定義書の対象範囲どおり在庫管理を伴わないため、書籍データとして登録されている書籍すべてを指すものとする（在庫切れ等による非表示制御はスコープ外）。
- 本機能は未ログインの一般利用者を対象とし、ユーザーごとの表示出し分け（おすすめ順・閲覧履歴等）は行わない。
- 検索・フィルター・並び替え（利用者による操作）は要件定義書§2で対象外と明記されている。一覧の表示順は登録順（ID昇順）で固定する（[Clarifications Session 2026-09-09](#clarifications) 参照）。
- 一覧のレイアウト・デザインの詳細（列数・レスポンシブ対応の具体仕様等）は技術選定書に定めるCSS方針（CSS Modules）に従い、設計フェーズ（`/speckit.plan`）で具体化する。
- 読み込み中（ローディング）状態の表示有無・具体的な見た目は本仕様では規定せず、設計フェーズで憲法§3のUX一貫性方針に沿って具体化する。
