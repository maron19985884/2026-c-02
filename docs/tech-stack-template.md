# 技術選定書（テンプレート）

> **位置づけ**: `/speckit.plan` を実行する **前に人間が記入する入力ドキュメント**です。
> ここに書いた技術方針をもとに Spec Kit が `plan.md` を生成します。
> 技術の「**選定**」は人間がこのファイルで確定させ、`plan` フェーズでは選び直さない前提です。
>
> 使い方: 本ファイルをコピーして各項目を埋め、プロジェクトに配置してから `/speckit.plan` を実行します。

## 1. 全体構成
- Docker Compose上に frontend（Next.js, 3000番）・backend（Express, 4000番）・db（MySQL, 3306番）の3コンテナ構成。frontendはApp RouterでSSR/CSRを行い、backendが提供するREST API経由でbackendがMySQLへアクセスする。

## 2. 使用技術スタック
| レイヤー | 採用技術 | バージョン | 選定理由 |
|---|---|---|---|
| フロントエンド | Next.js (App Router) | 14.x | 要件の画面遷移（一覧→詳細→カート→注文フォーム→完了）をファイルベースルーティングで素直に表現できるため |
| フロントエンド | React | 18.x | Next.js 14の標準ランタイム |
| フロントエンド／バックエンド共通 | TypeScript | 5.x | 憲法の保守性要件（型安全性の確保）に対応するため |
| バックエンド | Express | 4.x | 本プロジェクトの規模（学習・デモ用途）に対して軽量かつ実績があるため |
| バックエンド | mysql2 | ^3.x | Node.jsからMySQLへ接続する標準的なドライバ |
| データベース | MySQL | 8.0 | Docker公式イメージでの構築が容易で、要件のデータ規模（書籍数十冊）に対して十分な性能を持つため |
| インフラ・実行環境 | Docker Compose | - | `requirements.md`の制約条件（Docker Compose、frontend:3000／backend:4000）に準拠 |
| テスト | Vitest | ^4.x | フロントエンド・バックエンド共通のテストランナーとして設定を統一するため |
| テスト（API） | Supertest | ^7.x | ExpressのAPIエンドポイントに対する統合テスト用 |
| テスト（UI） | React Testing Library | ^16.x | Reactコンポーネントのテスト用 |
| フロントエンド（スタイリング） | プレーンCSS（`frontend/src/app/globals.css`をNext.jsのグローバルスタイルシートとして読み込み） | - | CSSフレームワーク未導入。本プロジェクトの規模（画面数枚）に対してTailwind等の導入コストが見合わないため、素のCSSに共通デザイントークン（CSSカスタムプロパティ）を定義する方式を採用 |

### 2.1 デザイントークン（`globals.css`で定義済み）

憲法セクション3「UX一貫性」に対応し、全画面で以下のトークン・共通クラスを使い回すこと。新規画面（注文フォーム・注文完了等）を追加する際も、独自の配色・余白を定義せずここに合わせる。

| トークン/クラス | 値・用途 |
|---|---|
| `--ink` / `--ink-muted` | 本文テキスト（濃い/薄い） |
| `--paper` / `--surface` | 背景色（ページ全体/カード等） |
| `--line` | ボーダー色 |
| `--accent` / `--accent-hover` | リンク・主要ボタンの配色（`#2f5fd9`系、設計書のブループリント配色と統一） |
| `--error` / `--error-bg` | エラー表示用 |
| `.page` | ページ共通コンテナ（`max-width: 960px`、中央寄せ、余白） |
| `.page__title` | 画面見出し（h1相当） |
| `.state-message` / `.state-message--error` | 読み込み中・空状態・見つかりません・エラーの共通メッセージ表示 |
| `.button` / `.button--primary` | ボタン共通スタイル |
| `.back-link` | 「一覧へ戻る」等の戻り導線 |

## 3. Lint・品質ツール
- 使用するLint（言語別）：ESLint（TypeScript対応、frontend/backend共通）
- 対応する設定ファイル：`frontend/.eslintrc` / `backend/.eslintrc`
- ※ 憲法セクション1（コード品質原則）および `.github/workflows/quality-gate.yml` のNode.js/TypeScript分岐と整合させる

## 4. 外部依存・連携
- 利用する外部API・サービス：なし（決済・外部連携はスコープ外）
- 既存システムとの連携点：なし（新規構築）

## 5. 制約・前提
