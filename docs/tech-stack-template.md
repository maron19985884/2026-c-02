# 技術選定書（テンプレート）

> **位置づけ**: `/speckit.plan` を実行する **前に人間が記入する入力ドキュメント**です。
> ここに書いた技術方針をもとに Spec Kit が `plan.md` を生成します。
> 技術の「**選定**」は人間がこのファイルで確定させ、`plan` フェーズでは選び直さない前提です。
>
> 使い方: 本ファイルをコピーして各項目を埋め、プロジェクトに配置してから `/speckit.plan` を実行します。

## 1. 全体構成
- アーキテクチャ概要（フロント／バック／DB の構成など。図があれば添付／リンク）：
  - フロントエンド（React + TypeScript / Next.js）とバックエンド（Node.js + TypeScript REST API）を分離した構成。
  - バックエンドはSQLite（ファイルDB）に書籍・カート・注文を永続化する。DBを別コンテナに分けず、バックエンドコンテナ内にDBファイルを持つ構成とする。
  - フロント・バックをそれぞれDockerコンテナ化し、`docker compose` でローカル一式を起動して動作確認する。

## 2. 使用技術スタック
| レイヤー | 採用技術 | バージョン | 選定理由 |
|---|---|---|---|
| フロントエンド | React + TypeScript / Next.js | 最新の安定版 | ユーザー要件定義書のUI要件（画面遷移中心の購買フロー）に対しNext.jsのルーティング・SSR/SSGが適合するため |
| バックエンド | Node.js + TypeScript（REST API） | 最新のLTS | フロントと言語（TypeScript）を統一し型共有・学習コストを下げるため |
| データベース | SQLite | 最新の安定版 | ログイン・決済・在庫管理を含まない小規模な購買フローデモのため、別DBサーバーを立てずファイル1つで完結させる |
| インフラ・実行環境 | Docker（ローカルコンテナ） | 最新の安定版 | 動作確認環境をローカルDockerに統一するため |
| CI/CD | 本ひな形の `.github/workflows/quality-gate.yml`（ESLint） | - | 追加のCI基盤を持たず、雛形のLint品質ゲートをそのまま流用する |

## 3. Lint・品質ツール
- 使用するLint（言語別）：TypeScript（フロント・バック共通）→ ESLint
- 対応する設定ファイル（`.eslintrc` / `pyproject.toml` 等）：`.eslintrc.json`（フロント・バックそれぞれに配置予定）
- ※ 憲法セクション1（コード品質原則）および `.github/workflows/quality-gate.yml` と整合させること

## 4. 外部依存・連携
- 利用する外部API・サービス：なし（ユーザー要件定義書のスコープ外に決済・在庫管理・検索等を明記）
- 既存システムとの連携点：なし（新規開発）

## 5. 制約・前提
- 使用禁止の技術／ライブラリ：特になし
- ライセンス上の制約：特になし
- チームのスキルセットなどの前提：TypeScriptでのフロント・バック開発を前提

## 6. 却下した選択肢（任意）
| 検討した技術 | 却下理由 |
|---|---|
| PostgreSQL | 本アプリはログイン・決済・在庫管理を含まない小規模な購買フローデモであり、別DBサーバー・DBコンテナを分離する構成は過剰と判断 |
| インメモリ（DBなし） | 再起動でカート・注文データが消えるため、動作確認（Phase 6）で作成した注文が残らず確認しづらい |
