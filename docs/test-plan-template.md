# テスト計画書（テンプレート）

> **位置づけ**: `/speckit.implement` 完了後、テストフェーズ開始前に **`/speckit.testplan` が本テンプレートをもとにテスト計画書を生成します**。
> 人間はその出力をレビューし、承認を得てからテストを開始します。
> `docs/guides/waterfall-preset-guide.md` のテストフェーズ承認ゲートに対応します。
>
> **使い方**: `/speckit.testplan` を実行する → 出力を `specs/[###]/test-plan.md` として保存する → 人間がレビュー・承認する。
> 本ファイル自体は AI の生成テンプレートです。直接編集する必要はありません。

## 3. 合否判定基準（Exit Criteria）

> テストフェーズの完了定義。すべての項目を満たしたらテスト完了とする。

- [ ] 単体テストのカバレッジが憲法セクション2で定義した目標値以上であること
- [ ] 結合テストが全件パスすること
- [ ] `spec.md` の全受け入れ基準（Acceptance Criteria）が確認済みであること
- [ ] Lint エラーが 0 件であること（`.github/workflows/quality-gate.yml` 参照）
- [ ] 未解決の重大バグ（Severity: Critical / High）が 0 件であること
- [ ] （プロジェクト固有の基準をここに追記する）

## 6. バグ管理方針

- バグ報告先：（例: GitHub Issues、Backlog 等）
- 重大度の定義：

| 重大度 | 定義 | 対応期限 |
|---|---|---|
| Critical | システム停止・データ破壊 | 即時 |
| High | 主要機能が使用不可 | テスト完了前に解消 |
| Medium | 一部機能に影響、回避策あり | 次スプリントまで |
| Low | 軽微な表示崩れ等 | プロジェクトで判断 |
