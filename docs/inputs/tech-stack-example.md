## 1. 全体構成

フロントエンド（Next.js）がブラウザからの画面表示を担当し、バックエンド（Express.js）へ REST API でアクセスする。バックエンドは MySQL に書籍・注文データを永続化する。フロントエンド・バックエンド・DB を Docker Compose でまとめてローカル起動する、学習・デモ用途の最小構成。

## 2. 使用技術スタック

| レイヤー | 採用技術 | バージョン | 選定理由 |
|---|---|---|---|
| フロントエンド | Next.js + TypeScript | Next.js 14 / TypeScript 5.4 | 商品一覧・詳細・カート・注文の画面遷移をファイルベースルーティングで簡潔に実装できる。要件定義書の非機能要件（保守性＝型安全性の確保）に合わせ TypeScript を採用 |
| バックエンド | Express.js + TypeScript | Node.js 20 LTS / Express 4 | REST API 3本（書籍一覧・詳細・注文作成）のみの小規模構成のため、軽量な Express で十分。フロントと言語を統一し学習コストを下げる |
| データベース | MySQL | 8.x | 書籍・注文というリレーショナルなデータ構造に適する。Docker公式イメージが安定しており、要件定義書の制約条件（Docker Compose前提）と合致する |
| インフラ・実行環境 | Docker / Docker Compose | Docker Desktop（Windows） | 要件定義書の制約条件どおり、フロントエンド port 3000・バックエンド port 4000 でローカル起動する構成をそのままコンテナ化する |
| CI/CD | 未導入 | — | 学習・デモ用途のためスコープ外。品質ゲート（Lint）のみ `.github/workflows/quality-gate.yml` で運用する |

## 3. Lint・品質ツール

- 使用するLint（言語別）：ESLint（TypeScript対応、フロントエンド・バックエンド共通）
- 対応する設定ファイル：`.eslintrc.json`
- ※ 憲法セクション1（コード品質原則）および `.github/workflows/quality-gate.yml` の Node.js/TypeScript 向けステップと整合させること

## 4. 外部依存・連携

- 利用する外部API・サービス：なし（決済処理・会員管理はスコープ外のため外部サービス連携も発生しない）
- 既存システムとの連携点：なし（スタンドアロン構成）

## 5. 制約・前提

- 使用禁止の技術／ライブラリ：認証・決済関連ライブラリ（憲法II章のスコープ外機能に該当するため導入しない）
- ライセンス上の制約：特になし（すべてOSSライブラリを使用）
- チームのスキルセットなどの前提：フロントエンド・バックエンドともにTypeScriptで統一し、担当者間の学習コストを抑える。要件定義書の非機能要件（セキュリティ＝`.env`での認証情報管理）を`docker-compose.yml`の環境変数注入で満たす

## 6. 却下した選択肢（任意）

| 検討した技術 | 却下理由 |
|---|---|
| React（Next.js不使用の素のSPA構成） | 商品一覧→詳細→カート→注文という複数画面の遷移をファイルベースルーティングで扱えるNext.jsの方が実装コストが低いため非選択 |
| PostgreSQL | 本サンプルの要件（書籍・注文のシンプルなリレーション）ではMySQLで十分であり、チームの既存知識との親和性を優先 |
| NestJS | 3エンドポイントのみの小規模APIに対しては過剰な構成のため見送り |
