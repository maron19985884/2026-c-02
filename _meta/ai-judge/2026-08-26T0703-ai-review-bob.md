## 詳細所見

### N-1（MEDIUM）: tasks-template.md の Phase 2 が Webアプリ構造のままで残存

- **対象**: `.specify/templates/tasks-template.md`
- **内容**: Phase 3 以降のタスクは `plan.md` の Structure Decision に連動する汎用表現（F-2 対応）に修正されたが、Phase 2（Foundational）の雛形タスクは以下のままで残っている：
  ```
  - [ ] T004 Setup database schema and migrations framework
  - [ ] T005 [P] Setup API routing and middleware structure
  ```
  これらは CLI/ライブラリ/デスクトップアプリ等では無関係な項目を含む。Phase 3 との一貫性を欠いており、`plan.md` の Project Type によっては削除が必要なことが利用者に伝わらない。
- **推奨対応**: Phase 2 の各タスク行に「`plan.md` の Project Type に依存する場合はタスクを削除または調整すること」旨の注記を追加する（Phase 3 と同様の警告行）。

### N-2（MEDIUM）: quality-gate.yml のフェイルセーフが言語追加時に壊れやすい

- **対象**: `.github/workflows/quality-gate.yml`
- **内容**: 対処21のフェイルセーフ（`hashFiles('package.json') == '' && hashFiles('pyproject.toml') == ''`）は正しい方向だが、Java/Go/Rust 向けブロックを追加した際にこの条件への追記を忘れると再びサイレントな緑になる。コメントで警告しているが、コードレベルでの検証は人間の注意に依存している。加えて、`testing-strategy-guide.md` が Java の詳細ガイドを提供しているにもかかわらず、CI の自動対応は Node.js/Python のみという不一致が依然として残っている。
- **推奨対応**: Java（`hashFiles('pom.xml') != '' || hashFiles('build.gradle') != ''`）のブロックとフェイルセーフ条件への追記を、最も使用頻度が高い言語として優先的に追加する。

### N-3（LOW）: requirements-template.md に実物ファイルへのリンクがない

- **対象**: `docs/inputs/requirements-template.md`
- **内容**: `docs/inputs/tech-stack-template.md` のヘッダーには「記入済みの実物は `../../tech-stack.md` を参照」というリンクがあるが、`requirements-template.md` には対応するリンク（実物は `../../requirements.md`）がない。同じ `docs/inputs/` 配下の対になるファイルとして、案内の形式が非対称になっている。
- **推奨対応**: `requirements-template.md` のヘッダーに「記入済みの実物は [`requirements.md`](../../requirements.md) を参照」を1行追加する。

### N-4（LOW）: how-to-use.md の準備手順に _meta/ 削除ステップがない

- **対象**: `docs/how-to-use.md` §3①
- **内容**: `_meta/README.md` には「新規プロジェクトとしてコピーする場合、このフォルダは不要なので削除して構いません」と記載されているが、実際の手順書である `how-to-use.md` §3①（雛形をコピーして Git リポジトリを作る）にこの削除ステップが含まれていない。多くの利用者は `how-to-use.md` を見ながらセットアップするため、README のみへの記載では見落とされる可能性がある。
- **推奨対応**: `how-to-use.md` §3①の手順に「`_meta/` フォルダは雛形の開発履歴であり、新規プロジェクトには不要なので削除する（任意）」を追加する。

### N-5（LOW）: CLAUDE.md のコマンド表が不完全

- **対象**: `CLAUDE.md` フェーズ別コマンド表
- **内容**: 現在の表にはコア5コマンド（`specify`/`plan`/`tasks`/`implement`/`analyze`）しか記載されておらず、後から追加された4コマンド（`/speckit.design`・`/speckit.review`・`/speckit.testplan`・`/speckit.change`）が掲載されていない。`CLAUDE.md` は Claude 起動時に読み込まれる設定ファイルであるため、ここに全コマンドが集約されていると、AI がより適切なタイミングでコマンドを提案できるようになる。`how-to-use.md` には全コマンドが記載されているが、AI の動作制御という観点では `CLAUDE.md` 側に揃える価値がある。
- **推奨対応**: `CLAUDE.md` のコマンド表に設計フェーズ（`/speckit.design`）・承認記録（`/speckit.review`）・テスト計画（`/speckit.testplan`）・変更要求（`/speckit.change`）の4行を追加する。
