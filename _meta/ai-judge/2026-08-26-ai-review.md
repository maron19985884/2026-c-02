## 詳細所見

### F-1（旧C-3の継続）: speckit.plan.md が技術選定書の存在を無視している

- **対象**: `.claude/commands/speckit.plan.md`
- **内容**: Key Rules に「Do NOT select technology — technology is defined in `requirements.md` and `constitution.md`」とあるが、技術を確定させる場所は憲法§5・CLAUDE.md・`how-to-use.md`§5のすべてが一致して技術選定書だと定めている。`plan-template.md`側のヘッダーは修正済みだが、コマンド本体のこの一文は据え置かれたままだった。
- **推奨対応**: 参照先を技術選定書に一文修正する。

### F-2（HIGH）: 「技術非依存化」が plan-template.md だけで止まり、下流に波及していない

- **対象**: `.specify/templates/tasks-template.md`、`.claude/commands/speckit.tasks.md`、`docs/detailed-design-template.md`（当時の配置）
- **内容**: `backend/src/models/[entity1].ts`等のWebアプリ構造の例示、および `backend/src/models/book.ts`・「Create Book model」という書籍アプリの残骸がそのまま残っている。タスク生成規則も「Models → Services → Endpoints → Frontend components」という層構造を固定しており、CLI/ライブラリ構成のプロジェクトにも frontend 層を前提としたタスクを生成しかねない。
- **推奨対応**: 例示パスと固有名詞を `plan.md` の Structure Decision に連動する汎用表現に置き換える。

### F-3（MEDIUM）: 設計フェーズの DoD が、同じ文書内の成果物一覧と矛盾している

- **対象**: `docs/waterfall-preset-guide.md`（フェーズ対応表と DoD）、`docs/review-gate-template.md`（当時の配置）
- **内容**: フェーズ対応表は設計フェーズの成果物として basic-design.md・detailed-design.md・table-definition.md を挙げているが、同じ文書内の DoD チェックリストはこの3つを一切チェックしない。
- **推奨対応**: 両ファイルの設計フェーズチェックリストに3成果物の確認項目を追加する。

### F-4（MEDIUM）: テスト戦略ガイドが、すでに存在するコマンドを「未実装」と書いている

- **対象**: `docs/testing-strategy-guide.md`
- **内容**: 「層1: コマンドファイル → 新規追加が必要（現存なし）」として `speckit.testplan.md` を挙げているが、このコマンドは既に実装済みで `how-to-use.md` からも案内されている。
- **推奨対応**: 現状に合わせて更新する。

### F-5（LOW）: 品質ゲートCIは Node.js と Python にしか実際には対応していない

- **対象**: `.github/workflows/quality-gate.yml`
- **内容**: 自動セットアップは Node.js・Python のみ。Java・Go・Rust は手動追記が必要。最終ステップ「Fail on Lint Errors」も `echo` するだけで実際には何も検査しない。
- **推奨対応**: 対応言語を広げるか、少なくとも未対応言語の場合に明示的に失敗させるフェイルセーフを入れる。

### F-6（LOW）: 前回の中程度指摘2件が、対応記録にも実物にも反映されていない

- **対象**: `ai-review.md`（M-4, L-2）、`.claude/commands/speckit.checklist.md`
- **内容**: 「テンプレート言語（英語/日本語混在）の統一方針を明記する」（M-4）と「`speckit.checklist.md` が `waterfall-preset-guide.md` の DoD を参照する」（L-2）は、`changelog.md` の対応7件のどれにも含まれておらず未着手。
- **推奨対応**: 対応するか、見送るなら理由を記録する。

### F-7（LOW）: 「この雛形自身の開発履歴」がテンプレート本体に同梱されている

- **対象**: `IBM Bob/`、`docs/ai-review.md`、`docs/changelog.md`、`docs/changelog-speckit-ai-driven-guide.md`、`docs/request-speckit-guide-2026-08-25-issue16.md`
- **内容**: `docs/ai-review.md` と `IBM Bob/spec-kit-ai-as-a-judge.html` は同一の62点評価を重複保持。制作過程の記録が `docs/` に同梱されているため、`how-to-use.md`§3①の「このリポジトリをコピーして新規プロジェクトを始める」運用に従うと、無関係な新規案件にも改修履歴が複製される。
- **推奨対応**: 制作過程の記録を複製対象外の場所に集約する。
